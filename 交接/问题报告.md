### 4.2 AionCore（`源码参考/software/AionCore`，ea24f50a，09-28）【源码】

- `crates/aionui-session/src/backend/` 下有四种通道：
  - `claude_conn.rs`：一个会话常驻一个 Claude 进程，解析它的流式输出；
  - `codex_conn.rs`：走 `codex app-server --stdio` 的 JSON-RPC。它会回应服务端发来的反向请求，避免卡死；遇到不认识的事件类型按数据处理，不会崩溃；
  - `antigravity/`：每轮启动一次 `agy`，用 `--conversation <id>` 接续，内含 argv、models、skills、translate、wire 几个模块；

- **非官方模型：** `crates/aionui-ai-agent/src/session_agent.rs:2005-2019` 读取 cc-switch 的配置，把 `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` 注入 Claude 进程。`cc_switch/model_info.rs:31-40` 从 `ANTHROPIC_DEFAULT_SONNET/OPUS/HAIKU_MODEL` 或 `ANTHROPIC_MODEL` 推出模型档位。
- **Skills：** 见 `源码参考/software/AionUi/docs/prds/conversations/acp/agent-skill-discovery.md`。
  - 用 `agent_metadata.native_skills_dirs` 记录每个 CLI 的原生技能目录：Claude `.claude/skills`、Gemini `.gemini/skills`、Qwen `.qwen/skills` 等；
  - 有原生目录的，把技能软链接进工作区；没有的，在首条消息注入技能索引；
  - ACP 协议本身没有标准的技能加载方法；
  - 热加载能力各不相同：Claude Code 会话中途能识别；Gemini 需要执行 `/skills reload`；Qwen 必须重启；
  - 该文档还指出：AionCore 给 Codex 配的 `.codex/skills` 和 OpenAI 当前文档写的 `.agents/skills` 不一致。

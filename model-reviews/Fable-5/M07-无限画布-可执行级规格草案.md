## 1. 使命与边界

**使命**:提供一个原生无限画布 surface,人和 Agent 通过同一动作路径创建/编辑/组织画布对象,全部写操作有权限、时间线证据与撤销。

**非目标**:
- 不做 iframe DOM 变异式设计器(D14);不自建渲染引擎(集成 OpenPencil React 版,见 §3)。
- 不做第二会话/资产存储:画布文档是"文档文件",时间线证据写 M00 SQLite,图片资产走 M05 Library。
- 不做实时多人协同(CRDT/OT)。v1 是"单用户 + 多 Agent"并发,冲突用 seq 仲裁,不做远程协同。
- 不在画布内渲染活体 Chromium/视频播放器(嵌入类节点只显示静态缩略图,点击跳转对应 surface)。
- 不做像素级绘图(画笔/矢量布尔运算)。v1 节点集见 §4。

**首个完整环(usable 判据的具体化)**:
人用工具栏建一个 text_frame → Agent 用 `canvas.node_create` 建一个 sticky → 两条事件都出现在时间线(actor 区分) → 人拖动 Agent 的节点 → Cmd/Ctrl+Z 依次撤销拖动与两次创建 → 画布回到空白,时间线含 `undo_applied` ×3。

## 2. 术语与坐标模型

- **canvas-space**:浮点无界坐标,原点 (0,0),无物理单位。节点存 `(cx, cy)` 为**节点中心**(与冻结 stub 的 cx/cy 一致,注:必须在实现里写死"中心点"语义,否则 F-Track B/D 会各写各的)。
- **viewport**:`{ cx, cy, zoom }`,zoom ∈ [0.05, 32],默认 1.0。
- 换算:`screenX = (node.cx - viewport.cx) * zoom + screenW/2`(Y 同理)。反向换算用于命中测试。
- **世界包围盒**:所有节点 AABB 的并集,供 minimap 与 viewport_fit 使用。

## 3. 引擎集成决策(恢复并细化)

**决策:集成 `ZSeven-W/openpencil`(React 版)作渲染层,Fleet 拥有语义层。** 禁用 Vue 版 `open-pencil/open-pencil`。
⚠️ 未验证项:该仓库的真实存在、活跃度、依赖树与许可证需在 F-Track A 开工前人工核验并把结论写入 REFERENCE-PROJECT-POLICY(上轮"证据不足"第 3 条)。**若核验不通过,回退方案 B**:基于 react + 自绘 SVG/Canvas2D 的最小渲染器(仅 §4 的 9 种节点、无手绘),工作量约为集成方案的 1.5–2 倍,但依赖为零——回退判据与工作量由 Lead 在 F-Track A 第 1 个交付物里确认。

**适配器架构(唯一允许触碰 OpenPencil 内部的层)**:

```
ActionInvocation ──► Hook 管道(M03:权限/租约/监督) ──► CanvasAdapter
                                                        │ translate()
                                                        ▼
                                            OpenPencil store 命令
                                                        │ history 事件
                                                        ▼
                     SessionEvent(M00 时间线) ◄── CanvasAdapter.emit()
```

适配器职责(仅三条):① Fleet action → OpenPencil 命令;② OpenPencil history 事件 → SessionEvent;③ 高频事件合并(§10)。**不做**权限、时间线直写、租约——那是 Hook 管道的事。

**F-Track A 的第一个交付物不是代码**,是映射表(§8 给出 v1 初稿),Lead 评审通过后才允许写适配器。

## 4. 节点类型与 data 载荷 Schema(新增——原稿缺失,不可执行的主因之一)

`CanvasNode.data` 按 type 定义(Zod 校验在 PostInvoke 前执行;遵循 M03 字段硬度原则:身份字段硬性、语义字段可选):

| type | data 载荷(必填 → 可选) | 说明 |
|---|---|---|
| `text_frame` | `{ text: string }` → `{ fontSize?: 12-96, align?: 'left'\|'center'\|'right', color?: token }` | 富文本 v1 仅纯文本+换行;富文本(TipTap)列为 v2 |
| `sticky` | `{ text: string }` → `{ color?: 8 色枚举 }` | 文本长度软限 500 字符,超限截断+notes |
| `image_asset` | `{ assetId: string }` → `{ fit?: 'contain'\|'cover' }` | assetId 必须是 M05 Library 资产;渲染层通过资产路径解析,禁止裸文件路径 |
| `code_block` | `{ code: string, lang?: string }` → `{ wrap?: boolean }` | 只读展示;编辑走 text 编辑器,不在画布内做 IDE |
| `browser_embed` | `{ snapshotRef: string, sourceUrl: string }` | 静态截图引用 + 来源;点击 → 打开 M06 surface。**无活体 webview** |
| `video_frame` | `{ assetId?: string, clipId?: string, posterRef: string }` | 海报帧 + 点击跳 M09;assetId/clipId 二选一必填 |
| `aigc_placeholder` | `{ jobId: string, status: 'pending'\|'running'\|'completed'\|'failed' }` | M08 任务完成后由 `canvas.node_update` 回填为 image_asset 语义(见 §12) |
| `connector` | (不用 data;用 CanvasEdge) | 见 C3;v1 直线 + 可选 label |
| `group` | `{ label?: string }` | 成员靠子节点的 `groupId` 反向确定;禁止嵌套 group(v1 硬限制,防递归复杂度) |

**通用约束**:width/height ∈ [8, 100000];新建默认尺寸按类型给定(text_frame 320×120、sticky 200×200、image 按资产宽高比,长边 480)。

## 5. 交互规格(恢复 + 跨平台修正)

快捷键统一写 `Mod`(mac=Cmd,win/linux=Ctrl;原稿硬编码 Cmd,不可跨平台执行):

| 手势/键 | 行为 | | 手势/键 | 行为 |
|---|---|---|---|---|
| Space+拖 / 中键拖 | 平移 | | Mod+Z / Mod+Shift+Z | 撤销/重做 |
| 滚轮 / 双指 | 以光标为中心缩放 | | Delete/Backspace | 删除选中(触发 L3 流程,§9) |
| Mod+= / Mod+- / Mod+0 | 步进缩放 / 100% | | Mod+G / Mod+Shift+G | 编组/解组 |

## 6. 持久化与恢复(新增细化)

- 每画布一份文档文件:`<workspace>/.fleet/canvas/<canvas-id>.json`,含 `schemaVersion: 1`。
- **写盘策略**:变更后 500ms 防抖写盘;写盘用 临时文件+原子改名;文档内含 `lastSeq`(最后已落盘的动作序号)。
- **崩溃恢复**:启动时若时间线中该 canvasId 存在 seq > lastSeq 的画布事件 → 提示"按时间线重放/放弃"二选一(重放 = 依序对文档应用事件 payload)。这利用了现有时间线,不引入第二存储。
- **与"No Second Store"红线的关系**:画布 JSON 是**文档**(用户可拷走的内容),不是状态存储;所有"谁改的/何时/能否撤销"只存 M00 SQLite 时间线。建议把这条判据写进 P2-25 提到的持久化分层总览。
- 文档迁移:schemaVersion 升级时提供纯函数迁移器 `migrate(vN) → vN+1`,禁止就地兼容读。

## 7. 撤销/重做模型(新增——原稿只有一句话)

- **文档级 LIFO 栈**,不是节点级(否决 IMPLEMENTATION.md 里的每节点 history 设计)。
- 栈元素 = `{ seq, actorRef, inverse: ActionInvocation }`;撤销 = 执行 inverse 并发 `undo_applied` 事件(inverse 同样过 Hook 管道,但跳过监督暂停,权限按 L1 记账)。
- **跨 actor 撤销语义(必须写死,否则 F-Track C 无法实现)**:人按 Mod+Z 撤销的是**本画布最近一次可撤销操作,无论谁做的**(与旧版 SPEC"Cmd+Z reverses either source"一致)。Agent 撤销只能撤**自己的** invocation(带 invocationId 定向撤销);撤销一个已被更高 seq 覆盖的操作 → no-op + `timeline_note`(说明被谁覆盖)。
- 重做栈在任何新写操作后清空。
- 不可撤销动作(node_delete 落地后)不入栈;其"恢复"路径 = 从时间线 payload 重建(v2,先不承诺)。
- 撤销深度:每画布 100 步(可配置),溢出丢最旧。

## 9. 权限、时间线与监督(细化)

- 全部写动作最低 L1;`canvas.node_delete` 为 **L3_destructive**(与冻结表一致):PreInvoke 发 `supervision_requested` → Captain(人审批界面)决议 → `supervision_resolved` 后执行。**例外**:目标节点由同一 invocation 链在本会话创建且无 edge/group 引用 → 降级 L1(写入事件 payload `downgradedFrom: 'L3'`,理由 `no_downstream_refs`)。
- **时间线合并规则(恢复)**:拖动/缩放过程中的中间态不发事件;指针抬起后合并为**一条** `canvas.node_update`。Agent 侧同理:同一 invocation 内多字段 patch 记一条。
- 每条画布事件的 `evidenceRefs` v1 为空数组即可;`canvas.export_selection` 产物路径必须写入其事件 evidenceRefs。
- 视图态动作(viewport_*、node_select)**不进时间线**(维持旧版决策,避免噪音)。

## 10. 并发与性能(恢复 OV-002 承载方案,补预算数字)

**这是 Owner 三大原始需求之一(OV-002),必须留在规格里**:

1. **帧批处理**:同一渲染帧(16ms)内到达的全部 mutate 收进一个批;整批应用到 store 后仅调度一次 `requestAnimationFrame` 重绘。禁止 setTimeout 防抖替代。
2. **批内排序**:按 `seq`(C1 裁决后的挂点)升序应用;同目标冲突时高 seq 胜,低 seq 记 `conflict_superseded` 事件。
3. **live 节点懒渲染**:`contentType:'live'`(aigc_placeholder 运行态等)出视口立即挂起换静态占位;回视口 200ms 稳定后恢复;zoom < 25% 全部转静态。v1 同屏活跃 live 节点上限 **3**。
4. **视口裁剪**:只渲染与视口相交的节点;空间索引 v1 用均匀网格(cell=1024),节点>5000 再评估四叉树。
5. **性能预算(验收可测)**:2,000 节点文档,平移/缩放 ≥ 55fps(基准机 = 开发机自测,记录机型);单帧 Agent 批 100 次 mutate 不掉帧;文档打开 ≤ 1s(2,000 节点)。
6. **降级路径**:超预算 → 先停 minimap 实时刷新 → 再降 live 节点为静态 → 最后提示用户拆分画布。禁止无声卡死(D36)。

## 11. Minimap 与导出

- Minimap:右下角可开关;渲染世界包围盒的降采样色块(不渲染内容细节);点击传送视口;只读。刷新频率 ≤ 4Hz。
- 导出:`png`(devicePixelRatio×2 渲染选区,白底/透明可选)与 `json`(选区子文档,含 schemaVersion)。导出文件落 `<workspace>/exports/canvas/`,路径写入事件 evidenceRefs。

## 15. 验收程序(Reviewer 可照跑)

1. 打开画布 surface → 新建 text_frame(工具栏)→ 时间线出现 `action_completed`(actor=human)。
2. Agent 调 `canvas.node_create` 建 sticky → 节点实时出现,事件 actor=agent。
3. Agent 调 `canvas.node_update` 移动人建的节点 → 人按 Mod+Z → 节点回原位,`undo_applied` 事件存在。
4. 删除有连线的节点 → 弹出监督确认(L3)→ 确认后节点与边消失,`supervision_requested/resolved` 成对出现。
5. 同帧内脚本发 50 次 update → 渲染只重绘一次(性能面板验证),事件 50 条、顺序=seq。
6. 关闭应用重开 → 文档完整;人为制造"落盘前崩溃"(kill)→ 重启出现重放提示。
7. 2,000 节点压测文档:平移缩放帧率达标;zoom 20% 时 live 节点全部为静态占位。

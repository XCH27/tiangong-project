# M16 工作台多面板系统(Workbench Panel System)— 规格草案(新模块提案)

> 性质:审查模型(Fable-5)起草的**建议稿**。
> 对"多功能面板"的解读:**工作台的可停靠多面板/布局系统**——承载各 surface(画布/浏览器/视频)与工具面板(文件、任务、终端、时间线证据等),即 OWNER-VOICE OV-001 里 Owner 说的"增加工具面板之类的"的承载层。若 Owner 所指是别的(例如仅 M08 任务面板的 UI),请指出,本稿大部分内容仍适用于那个面板的宿主层。

---

## 0. 为什么必须有这个模块(现状是空白)

1. **没有任何模块拥有面板/布局系统**:OWNERSHIP-MATRIX 里 M00 拥有 `renderer/shell/`,M13 拥有设置页,M06/M07/M08/M09 各拥有自己的 surface 目录——但"surface 如何被打开、停靠、分栏、恢复布局"无人负责。这正是 PARALLEL 模型警告的失败模式:每个后端模块自己发明面板 → 无人协调 → 第二 UI 真相。
2. **多个现有规格已经隐式依赖它**:M08 说自己是"auxiliary panel + 左侧栏图标 + badge 计数";M02 需要"终端面板";M06/M07/M09 是"peer surface,替换主区域";M05 有"files panel"。这些悬空引用需要一个真实宿主。
3. **D35/OV-001 的可扩展性承诺需要它**:未来"增强浏览器功能/加工具面板"若无面板注册表,只能改壳代码——违背"新能力可插拔"的决策。
4. **D18** 说"默认工作台 + 四个专业 surface 是 surfaces 不是独立 app"——这句话的工程含义就是本模块。

## 1. 使命与边界

**使命**:提供工作台唯一的面板注册、布局、路由与持久化系统。任何模块/插件通过**注册**获得 UI 落点,而不是自行修改壳。

**非目标**:
- 不替换 Craft 壳(D27-R):本模块是壳内的布局管理层,复用现有 app-shell 组件与 tokens。
- 不做自由浮动多窗口(v1 不做 tear-off 独立 OS 窗口)。
- 不做第二设置存储:布局快照存现有 preferences/设置体系。
- 不复制 Dockview / react-resizable-panels 源码(两者在参考目录中均为**禁止拷贝**边界;只允许行为参考:布局序列化思想、尺寸分配思想)。

## 2. 概念模型

```
WorkbenchLayout
 ├─ MainArea(单例):承载一个 SurfaceRoute(chat/canvas/browser/video/aigc/settings…)
 │    └─ 可选水平二分(v1 最多 2 个 surface 并排,如 chat+browser)
 ├─ SideDock(left|right):PanelStack,tab 化的工具面板(files/jobs/timeline/…)
 ├─ BottomDock:PanelStack(终端面板的默认落点)
 └─ StatusBar / TopBar:M00 壳所有,本模块不动
```

### 2.1 类型定义(建议进入 contracts,minor 扩展)

```ts
export type PanelSlot = 'left' | 'right' | 'bottom' | 'main';

export interface PanelDefinition {
  panelId: string;            // 命名空间规则同 M12:'fleet.files' | '<surface>.<plugin-id>.<name>'
  title: string;              // i18n key
  slot: PanelSlot;            // 默认落点(用户可移动,main 仅 surface 可用)
  icon: string;               // 图标 token
  minSize: { w: number; h: number };
  ownerModule: string;        // 'M05' | 'M08' | 'plugin:<id>'
  badge?: 'none' | 'count';   // M08 运行中任务数等
  lazyMount: boolean;         // 默认 true:不可见即卸载(与 M07 live 节点同哲学)
}

export interface SurfaceRoute {
  surfaceId: string;          // 'fleet.surface.canvas' 等
  documentRef?: string;       // canvasId / clipId / url…
}

export interface LayoutSnapshot {
  schemaVersion: 1;
  main: SurfaceRoute[];             // 1 或 2 个
  docks: Record<Exclude<PanelSlot,'main'>, { open: boolean; size: number; activePanelId?: string; order: string[] }>;
  savedAt: string;                  // ISO 8601
}
```

## 3. 硬规则(与既有决策对齐)

1. **注册制,不许硬接**:任何面板/surface 进 UI 必须经 `PanelRegistry.register(def)`;注册表校验命名空间(复用 M12 规则:`fleet.*` 保留给核心;插件必须用自己的 namespace;冲突拒绝,不静默覆盖)。
2. **UI 落点仍归 Lead**(UI Rule 不变):模块的 PanelDefinition 中 `slot` 是 Lead 在规格里定的;Worker 不得自定。本模块提供机制,不转移决策权。
3. **面板是视图态**:开/关/换 tab/调尺寸不进时间线(与 M07 视口决策同源)。唯一例外:插件面板首次安装启用(走 M12 权限,L2)。
4. **Agent 可见性**:提供两个 L0 动作(需冻结):`panel.open`(`{panelId}`)与 `surface.open`(`{surfaceId, documentRef?}`)——Agent 用于"把证据带到用户眼前"(如打开时间线面板定位到某事件、打开画布定位节点,与 `canvas.zoom_to_node` 串联)。只读、不进时间线、可被用户在设置里关闭("Agent 不得操纵我的布局"开关,默认允许)。
5. **布局持久化**:LayoutSnapshot 按 workspace 存进现有 preferences;启动恢复;损坏则回默认布局并提示(不崩溃)。`layout.reset` 命令面板可用。
6. **懒挂载**:不可见面板卸载 React 子树(保 OV-002 的性能关切);终端面板例外——进程仍活,仅 UI 卸载,PTY 缓冲由 M02 持有。

## 4. v1 面板清单(核心注册项,Lead 定稿)

| panelId | slot | owner | 说明 |
|---|---|---|---|
| `fleet.files` | left | M05 | 工作区文件树 + Library 页签 |
| `fleet.timeline` | right | M00 | 会话时间线/证据查看器(支持 eventId 定位) |

M06/M07/M09 规格中的"opens as a full-screen surface / not embedded inside the chat panel"语句改写为"注册为 main slot 的 SurfaceRoute"。

## 5. 波次与归属(提案)

- **模块号 M16**,规格文件 `docs/modules/16-panel-system.md`。
- **拆两刀**:
  - **M16a 骨架(建议排 W2)**:PanelRegistry + MainArea 单 surface 路由 + BottomDock(只为 M02 终端面板服务)+ 布局持久化。理由:M02 在 W2 需要终端面板落点,否则 M02 又会自己造壳。
  - **M16b 完整(排 W3,与 surfaces 同波)**:SideDock、双 surface 分栏、badge、`panel.open/surface.open` 动作、插件面板通道(与 M12 对接的部分推迟到 W4)。
- **OWNERSHIP-MATRIX 增补**:`app/apps/electron/src/renderer/workbench/`(新目录)→ M16 Worker;`renderer/components/`(共享组件)仍 Lead。
- **WAVE-MODULE-MAP 增补** M16 行 + W2 gate 注记("M02 依赖 M16a")。

## 7. 验收程序

1. 启动默认布局:chat surface + files(left)+ terminal(bottom,折叠)。
2. 打开画布 surface → main 区切换;侧栏与底栏不受影响;重启后布局恢复。
3. 拖动分隔条改尺寸 → 重启保持;`layout.reset` 恢复默认。
4. 注册一个假插件面板(测试用 namespace)→ 出现在指定 dock;命名冲突注册被拒绝且有用户可见错误。
5. Agent 调 `panel.open {fleet.timeline}` → 面板展开;设置里关闭"允许 Agent 控制布局"后同调用返回被拒事件。
6. 500 条 jobs 列表在 badge 面板关闭时不占渲染(懒挂载验证:React devtools 无该子树)。

## 8. 开放问题(Lead 裁决)

1. M16 的模块号/命名是否接受;M16a 是否如提案排进 W2(影响 map 与 wave-2 packet)。
2. `surface.open` 与既有会话路由(chat)的关系:chat 是否也收敛为 SurfaceRoute(建议:是,但 M01 波内只做适配不改行为)。
3. 双 surface 分栏(chat+browser)是否 v1 承诺(建议:M16b 承诺,画布类重 surface 禁止分栏以保性能)。
4. 布局是否分"每 workspace"与"全局默认"两层(建议:是,workspace 覆盖全局)。

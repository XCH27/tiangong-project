## 逐模块缺失项清单(达到可执行需补齐的具体条目)

### M00 平台脊柱 🔴(W1,已开放——最高优先)
规格从 73 行改写为 42 行"接口卡"后,Worker 无法回答任何一个实现问题:
1. **SQLite 表结构**:sessions / session_events / leases / audit 至少四张表的字段、索引(sessionId+seq 唯一索引?)、WAL 模式声明。SessionEvent 的 stub 有了,但**存储映射**(JSON 列 vs 展开列)没有。
2. **事件总线接口签名**:`emit(event) / subscribe(filter, cb)` 的同步性、背压、跨进程(Bun server ↔ Electron)传播方式——一个字都没有。
3. **权限评估器 API**:`checkPermission(actor, actionDef, targets) → PermissionDecision` 的输入输出、L2"pre-authorization 规则"的存储位置(D12 说 L2 可预授权,谁存这个规则?)。
4. **`AgentSession.create()` 签名**:与 P0-6 的 AgentSeat 双表示矛盾绑定——tags 数组还是结构化字段,必须先裁决。
5. **WS 鉴权**:token 如何生成/存放/校验(M02 依赖)。
6. **验收标准不可测**:"No concurrent SQLite busy locks during parallel reads"——WAL 下读不加写锁,此句恒真;应改为可测项(如"两个连接并发 100 写/秒无 SQLITE_BUSY 且事件 seq 无空洞")。
7. Agent Hooks(`sessions:listEvents/checkPermission`)缺参数与返回值 schema。

### M01 清理基线 🟡(W2)
1. 缺**清理对象清单**:哪些是"Fleet experiments that fight the direction"?需要 Lead 给出目录/组件级列表或判定规则(旧版有三分类,但没有落到路径)。
2. "删除需 rg 证据 + Lead 批准"保留了,但没有 rg 证据的格式模板。
3. 上游同步操作步骤(oss-sync 流程、冲突处理)缺失。

### M02 终端 CLI 运行时 🔴(W2)
新版把旧版的实体内容全删了,只剩安全红线:
1. **运行时目录/检测**(旧版 `CliRuntimeDefinition`、detected/custom、PATH 诊断)全部消失——没有它,"选择或检测一个 runtime"这个用户环节无法实现。
2. **转写(transcript)模型**:输出块如何分段、ANSI 处理、行数上限、与时间线的关系(全量入库还是引用文件)。
3. **停止/杀进程语义**:SIGTERM→SIGKILL 升级时序、进程组、孤儿进程清理。
4. **权限映射**:哪类命令 L1、哪类 L2/L3(旧版"by risk"也只有一句;需要一张命令风险分级表或声明"v1 全部 L2 需确认")。
5. **PTY 宿主**:写死 Electron main(Node),删除"/Bun layers"字样(与 INTEGRATION-PLAN §1.4 对齐)。
6. `.fleet/session.lock` 与 socket/端口/token 的发现机制(见 M00 第 5 条,双向依赖)。
7. 终端面板 UI 落点 → 依赖 M16a(见面板提案 §5)。

### M03 动作注册表 🔴(W1,已开放)
1. **注册表 API 签名**:`register(def) / get(id) / list(filter) / invoke(invocation) → Result` + `ActionManifest` 构建函数(身份矩阵引用了它,无定义)。
2. **Hook 管道细节**:PreInvoke 三步(权限/租约/监督)与 PostInvoke 三步(归一化/置信度降级/错误包装)在旧版是完整的,现在只剩一句话——恢复旧 §9 全文。
3. **错误分类**:`errorCategory: transient|validation|business|permission` + `isRetryable` 随重写消失,必须恢复(M08/M11 的重试逻辑依赖它)。
4. **Schema 设计原则(旧 §8.1–8.5)**:D33/D34 还在引用,内容已无处安放——建议独立成 `contracts/schema-principles.md`。
5. 执行器注册方式:各 surface 的 executor 如何挂到 action id(静态 import 表还是运行时注册)。
6. `ActionSuccessEvent` 与 stub 枚举 `action_completed` 的命名冲突需消除。

## 一个通用教训

本轮"规格瘦身"把**接口卡**(10 节新格式)当成了**规格**。接口卡适合做模块间合同摘要,但 Worker 开工需要的是:字段表、签名、边界行为、验收步骤。建议双层结构:每模块 `SPEC.md`(完整,含上述四件套)+ 顶部一屏"合同摘要"(现在的 10 节格式),摘要从正文提炼,不再单独维护第二真相。

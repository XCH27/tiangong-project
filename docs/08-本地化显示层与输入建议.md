# 08 · 本地化显示层 + 输入建议（你的问题 1 / 2 / 3）

> 覆盖：插件市场自动同步 + 自动汉化（1）、CLI/Skill 说明自动汉化但**不改原文**（2）、输入框记忆建议 + 快捷用语（3）。
> **共同原则：翻译只在显示层，执行/存储/匹配永远用原文**——与 `07` 的适配层思想一致。

## 1 · 本地化显示层（统一治 1、2）

问题本质相同：英文的**插件说明 / CLI 命令说明 / Skill 描述**，要给中文用户看中文，但**绝不改动**原始命令、Skill 文件、插件包（一改就破坏执行，也违反"不另起第二套真相"）。

**做法 = 翻译缓存层**：
- 外部文本（插件 `description`、CLI `--help`/命令、Skill frontmatter `description`）进来 → 算 hash → 查本地译文缓存 → 命中显示中文，未命中后台翻译（本地/云模型）后入缓存。
- **UI 显示译文；执行 / 存储 / 匹配永远用原文**：命令照原样跑、Skill 照原样注入、插件照原样安装。
- 每条译文带"显示原文"开关；用户可纠正（用户译文优先，回写缓存）。
- 对 craft 是**只读旁路**：不动 Skill 文件、不动 CLI、不动插件包。

落点：`LocalizationService`（`hash → 译文` 的 SQLite 缓存）+ renderer 在渲染说明处调用它。

## 2 · 插件市场：自动同步 + 自动汉化（问题 1）

- **不自创格式**：建在 **MCP server(+registry) + Skills + Claude Code plugin/marketplace** 标准上。
- **自动同步（不用一个个手动）**：marketplace 是**git 托管的清单(manifest)**——定期拉清单 diff，列出"有更新的插件"，提供**一键 / 可选自动更新**。同步的是"有哪些插件、什么版本"；更新与否可设自动 or 手动。
- **自动汉化说明**：插件 `name/description/README` 过第 1 节本地化层 → 列表显示中文，**插件包本身零改动**（仍原样安装运行）。CowAgent 的 Skill Hub、Claude Code marketplace 都是 git 清单式，正好这么处理。

## 3 · CLI 命令 / Skill 说明自动汉化（问题 2）

- **CLI**：连接时抓 `--help`/命令列表 → 本地化层翻译 → UI 显示中文说明；**真正执行用原命令**。翻的是"说明 / 按钮文案"，不是命令本身。
- **Skill**：读 Skill frontmatter `description` → 翻译显示；**注入模型 / 触发匹配仍用原文**，保证 Skill 行为不变。
- 一句话：**只翻"给人看的说明"，不翻"给机器执行的命令 / Skill 正文"。**

## 4 · 输入框记忆建议 + 快捷用语（问题 3）

输入框上方一行，两类可点建议：

1. **记忆建议**：按 D2 记忆 + 历史对话，匹配你**常说的话 / 常用提示词**浮出几条。来源 = 记忆层检索（你的高频句 = 高频语义记忆）。
2. **快捷用语（snippet / 扩展）**：你**自定义**触发词 → 展开内容。例：输入 `转3d` → 浮出你预设的几条生图提示词，点了把全文填进输入框。
   - 数据：本地 `snippets` 表 `{触发词, 候选展开[], 标签}`，用户可增删改。
   - 匹配：前缀 / 关键词触发；多候选就列出来选。

**两者咬合**：记忆建议来自"看你历史"，快捷用语来自"你预设"——这正是你要的，且直接复用 D2 记忆（点 3 配合点 6）。

落点：renderer 输入框组件 + `SuggestionService`（读记忆检索 + snippets 表）；snippets 写进 craft config、记忆走记忆库，**不另起第二套**。

## 5 · 共同验收

- **译文层**：只改显示，**原始命令 / Skill 文件 / 插件包零改动**（可 diff 验证）；关掉本地化 = 回英文原文。
- **插件市场**：清单同步能列出"有更新"；自动 / 手动可选；说明显示中文、包不变。
- **输入建议**：常用语自动浮现；`转3d` 触发预设提示词；snippets 可增删改。

> 边界：以上都属"显示 / 旁路"层，**不碰执行真相**，因此对 craft 升级、插件原作者都零侵入，符合 `07` 的少更新原则。

## 7 · 功能 2 落地：`/` 命令 与 `@` Skill 的短中文说明（实测已通路）

实测 craft：
- **`@` Skill 本就有 `description`**：`packages/session-tools-core/src/validation.ts` 强制要求，`packages/shared/src/skills/storage.ts` 存进 `metadata.description`——**只是 `@` 菜单没显示**。
- **菜单组件**：`apps/electron/src/renderer/components/ui/skill-mention-menu.tsx`、`mention-menu.tsx`（@）；`slash-command-menu.tsx`（/）。

接法：
1. **`@` Skill**：在 `skill-mention-menu.tsx` 名字旁显示 `metadata.description`，过 `LocalizationService.localize(desc,'skill')` → 短中文；`peek` 先返缓存/原文，翻好再刷新。**不动 skill 文件**。
2. **`/` 命令**：内置命令是小而固定的集合 → 建一份**人工策展映射** `curated`（最准，例 `/clear`→"清空会话"、`/compact`→"压缩上下文"）；自定义命令有 description 就翻、没有先只显示名。改 `slash-command-menu.tsx`。
3. 全程显示层：**执行 `/` 命令、注入 `@` Skill 仍用原文**。

> 这步是 UI 改动：用户已明确要求。当前环境可运行 craft，菜单组件应由当前执行 agent 直接接入并验证；不要再把它写成“交给别的执行者”的悬空任务。

## 8 · 功能 1 落地：插件市场（市场更大，分步）

- **市场标准**：MCP server(+registry) + Skills + Claude Code plugin/marketplace（git 清单）。craft 已有 Skill 导入 / Sources，市场 = 在其上加"浏览 + 安装 + 更新"。
- **自动同步**：定期拉清单 diff → 列"有更新" → 一键 / 可设自动更新。
- **汉化说明**：插件 `name/description` 过同一个 `LocalizationService.localize(desc,'plugin')`，列表显示中文，**插件包零改动**。
- 工程提示：功能 1、2 **共用上面这个引擎**；功能 2 已实测通路、即时可见——可先用它把引擎在真界面验证，再铺功能 1 市场。

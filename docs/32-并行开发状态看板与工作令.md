# 32 · 并行开发状态看板与工作令（冲突隔离 · 单一真相）

> 状态日期：2026-06-22
> 作用：让多个工程 Agent **同时开发且互不干扰、不跑偏**。它回答四件事：现在做了什么 / 谁拥有哪些文件 / 按什么波次并行 / 每个任务怎么验收。
> 口径：只按主线 `work/fresh-base-spine` 的**已提交代码**判断状态；其它 worktree、口头“已完成”都不算主线完成（铁律 23）。
> 配套：契约真相见 `docs/33`（团队）/`docs/31`（动作脊柱）/`docs/30`（架构）；**每个 Agent 的完整提示词见 `docs/34`**。

---

## 0 · 不互相干扰的唯一机制：契约冻结 + 硬文件所有权

并行最大的事故源是**多个 Agent 抢改同一个共享契约文件**（`channels.ts`/`routing.ts`/`dto.ts`/`index.ts`/`channel-map.ts`/`types.ts`/i18n JSON/handler 注册）。本看板用两条铁律消除它：

1. **契约只由 Lead 改（Wave 0）。** 所有跨 Agent 需要的 channel、event、command、type、i18n key、handler 注册，由 **Lead 在 Wave 0 一次性冻结并合入主线**。冻结后这些文件**对并行 Agent 只读**。任何并行 Agent 需要新契约 → 回 Lead，不得自己加字段（否则必冲突 + 漂移）。
2. **每个文件恰好一个所有者。** 见 §3 文件所有权矩阵。Agent 只改自己拥有的文件，**禁改清单是硬约束**。新 handler 文件用「Lead 在 Wave 0 建空壳并注册 → 该 Agent 在 Wave 1 填实现」的**顺序移交**（不是并发同改）：Wave 0 后 Lead 永不再碰该文件。

只要遵守这两条，N 个 Agent 的 diff 在文件级天然不相交，可无冲突合入。

## 1 · 状态标记规则

| 标记 | 含义 |
|---|---|
| ✅ 已落主线 | 已提交，可作依赖 |
| 🟨 已有基础 | 部分落地，未成闭环 |
| ⛔ 未开始 | 必须另开任务，不能假装完成 |
| 🧊 冻结收口 | 只修 bug/接线，不扩功能 |
| 🔒 Lead 独占 | 只能 Lead 改，不可拆并行 |
| 🧩 可并行 | 边界清楚，独立 Agent 可做 |

**汇报硬规则**：任何 Agent 汇报完成必须含：worktree、branch、commit、改了哪些文件、没碰哪些禁改文件、跑了哪些验证、是否污染主线（格式见 §6）。缺项不算完成。

## 4 · 波次计划（依赖顺序）

```
Wave 0 (Lead 独占, 阻塞)        Wave 1 (团队功能并行)               Wave 2 (其它域另行冻结契约)
提交团队协议/rules 基线          Lead: TeamCoordinator + 管理Agent投影  全部文件 + Library
核准真实文件落点与 i18n key      A1: @// 输入迁移                     External Job
合入主线 ──────────────▶        A2: 会话列表团队化 UI                管理Agent UI + 端到端集成
```

- **Wave 0 必须先合入主线**，并行 Agent 才能 `git pull` 到冻结契约后开工。
- **当前可安全并发上限：Wave 1 同时 3 路**（Lead 做 Coordinator + A1 + A2）。全部文件/Library 与 External Job 必须分别完成源码勘探和契约冻结后再放行，不能借团队协议顺便预造两套新协议。
- A2 的写操作（提升队长、发团队消息、分派）在 Lead 的 Coordinator 合入前先接 disabled / 空 handler；契约里命令已在，UI 先渲染后通电。
- 每个并行 Agent 在**独立 worktree + 独立分支**开发，完成后按 §6 汇报，由 Lead/人类串行合入。

## 5 · 最容易跑偏的点（所有 Agent 必读）

1. **不碰共享契约。** 需要新 channel/event/type → 回 Lead，不自己加（§0）。
2. **不建第二套 session/team/store。** 只用 craft `SessionManager`/`SessionEvent`/permission（铁律 13）。
3. **不假执行。** 没接后端的写操作必须 disabled 或明确报错，不能谎称完成（铁律 23）。
4. **`@` 只找人，`/` 才是 Skill/命令/模板。** 不让 `@` 再调 Skill。
5. **队长不是超级权限。** 能分派/汇总/请求审查；不能绕 permission、不能自动同意 L3。最高是管理 Agent，但它也不绕 permission。
6. **投递 ≠ 运行。** 发消息/建任务是 L1 投递；`autoRun` 启动 agent 运行是 L2（`docs/33` §0）。
7. **全部文件是 raw view，不是知识库；Library 才是资产层。**
8. **Warp 只学行为，不抄源码/schema/UI。**

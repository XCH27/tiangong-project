# 18 · 界面信息架构与人机协作总设计

> 状态日期：2026-06-24
> 效力：本文是 Fleet 当前界面方向的单一真相。与旧的“Workbench 三栏壳、全局 Action Ticker、通用 Inspector”冲突时，以本文为准。
> 当前代码状态：默认工作台仍基于 Craft 原界面。已落：身份标签收敛到原标签系统、团队群聊特殊会话项、会话模型/Runtime 图标、管理 Agent 右下角入口、管理 Agent 模型/自动决策设置、独立记忆设置与 Agent 记忆工具、Token 环弹层估算、`/` Skill/Source 入口、右侧上下文栏（Progress + 当前工作区文件只读浏览/预览）。仍未完成：真正“所有会话”层管理 Agent 专栏、`@Agent/@身份` 搜索、Library 资产层、文件整理写操作、四个专业工作面。

---

## 1 · 核心原则

1. **默认界面不重做。** 保留 Craft 原有的工作区、会话列表、聊天面板、标签、设置和 BrowserPane 设计语言；只在原挂点上改字段、增必要入口。
2. **专业功能先独立跑通。** 无限画布、AIGC、网页/文档、视频剪辑可以有自己的整页布局和原生引擎，不强塞进默认聊天页。
3. **共用底层，不共用错误的壳。** 各工作面共用工作区、全部文件/Library、Agent、记忆、permission、session timeline、成本账本和导出；选区、属性面板、撤销与内容模型由各原生引擎负责。
4. **人和 Agent 共用能力契约。** 人在界面执行的写操作，Agent 必须有结构化工具可以完成；两者均经过同一 permission，并写入同一 session timeline。
5. **不做假功能。** 未接真实后端、原生引擎或会话路由的按钮不得显示为可用。

## 2 · 顶层导航

### 2.1 默认工作台

默认工作台继续使用 Craft 原结构：

- 左侧：工作区与原导航。
- 中间：“所有会话”及原 Craft 会话列表。
- 右侧：上下文栏，上面是当前会话任务看板（Progress），下面是当前工作区文件夹文件；右侧按钮可整体隐藏/显示。
- 右上角 Agent 专用浏览器保持现有用途，不与网页/文档工作面混为一个入口。

不在默认页增加第二套工作台壳、全局底部动作条、通用三栏 Inspector 或团队控制台。

### 2.2 专业工作面

| 工作面 | 核心用途 | 界面中心 | 原生引擎方向 |
|---|---|---|---|
| 无限画布 | UI/网页设计、图片编辑、分镜编排、素材组合 | 画布 + 图层 + 属性 + 素材 | 优先研究 openpencil；迁码需先绿灯 |
| AIGC | 从生图、图像处理、3D 资产到生视频的任务链 | 节点/任务流 + 结果预览 + 素材 | External Job + 用户授权的 Web/API provider |
| 网页/文档 | 访问网站、标注、网页与文档编辑 | BrowserPane/文档主区 + 原生属性或批注 | Craft BrowserPane/CDP + 文档模型 |
| 视频剪辑 | 剪辑视频、AI 生成片段与网页动画 | 预览 + 轨道时间线 + 属性 + 素材 | 优先研究 OpenCut Classic；迁码需先绿灯 |

专业工作面可以使用同一套导航入口和切换规则，但不强制相同布局。

## 3 · 所有会话与团队

### 3.1 会话列表只改原字段

- 团队状态显示为：待安排、进行中、待审查、完成、取消。
- 每条会话可增量显示模型/Runtime 图标、稳定序号和原标签中的身份。
- 模型/Runtime 图标仅用于识别，不可点击升队长。
- 稳定序号按工作区前缀 + 会话创建时间派生，不随最近消息排序改变，不写入标签。

### 3.2 原标签系统升级身份能力

- 只有一套 Craft 标签定义和 session `labels`。
- 标签可选指定“身份用途、系统提示词、permission profile 引用”；未指定时仍是原普通标签。
- `队长` 是原标签中的特殊身份，添加/取消标签就是提升/取消队长。
- 不新增“身份标签”子菜单、队长按钮、独立身份 store 或重复设置页。

### 3.3 团队群聊

- “所有会话”顶部只出现一条与原会话相同样式的特殊会话项：群聊图标 + “团队群聊”。队长只影响花名册/调度，不影响入口存在。
- 打开它后仍是原 Craft 聊天面板和原输入框，不在会话列表加输入框。
- 团队群聊像真实团队群，只显示队长安排、成员汇报、成员提出的问题/意见、待审提醒和少量方向性摘要；它不是把所有成员会话完整合并进来。
- 群聊消息必须尽量短，让人类能快速判断“现在谁在做什么、做完了什么、有没有阻塞、项目方向是否正确”。完整思考过程、工具输出、长代码和长审查报告留在成员会话或报告文件里。
- 需要看完整执行过程时，再从群聊卡片跳回对应成员会话，并按权限读取。
- 不带 `@` 表示广播给团队有效成员；不提供 `@所有人` 这种额外语法。`@会话/Agent/身份` 是定向消息，只进入目标成员上下文，不能靠前端隐藏来伪装隔离。
- 队员进入“待审查”时，团队群聊只插入一条待审简报卡，包含成员头像、模型/Runtime、稳定序号、身份标签、任务号、报告摘要和源会话入口，不直接复制成员完整对话。
- 消息和工作简报显示发送者头像、模型/Runtime、稳定序号和身份标签；这些都是显示投影，真实来源仍是 session、label 和事件。

### 3.4 常驻管理 Agent

- 长期形态是在“所有会话”层有跨工作区的软件级入口，不作为某个工作区的普通会话。
- 当前代码先落右下角 Multica 式唤起/最小化入口；首次发送会创建 hidden craft session，按管理设置选择模型，并注入管理 Agent 专用系统提示词。它复用原 `onSendMessage`、permission、tool 和 timeline，不是第二套会话系统。
- 管理 Agent 可管设置、Skill、记忆、素材和跨项目协调，但写入、外发、删除和发布仍走 permission 与 L0-L3。
- 有队长时只读队长摘要；无队长时才读普通 Agent 摘要。深读成员上下文必须授权。

## 4 · 全部文件与 Library

- “全部文件”直接展示“我的工作区”和用户授权的本地目录，可按图片、Markdown、网页、视频、音频、PPT、代码、字体等过滤。
- 当前代码先落最小 raw view：默认工作台右侧上下文栏显示当前工作区根目录下的文件/文件夹；点选文件走原 `FileViewer` 预览。它是只读闭环，不提供移动、重命名或删除。
- 工作区顶部 `My Workspace` 等可翻译字段显示为“我的工作区”；通用 `Workspace` 显示为“工作区”，通过 i18n 修改，不破坏多语言。
- “本地文件夹”数据源的产品中文为“本地知识库”，它仍属于数据源，不等于“全部文件”。
- Library 是项目选用、授权和建立来源记录后的资产层，不另复制一份存储。各专业工作面共用同一本地文件与 Library。
- AI 新建目录、分类、移动、重命名和删除文件均走 permission + timeline，不做 renderer 私有状态。

## 5 · 人和 Agent 如何共用工作面

| 层 | 人类 | Agent | 共同要求 |
|---|---|---|---|
| 选区 | 鼠标、框选、多选、时间区间 | 结构化 `select` 工具 | 选区引用可被说明和重放 |
| 读取 | 看画布/属性/轨道 | `read` 返回结构化模型 | 不依赖反复截图找按钮 |
| 编辑 | 拖拽、属性、时间线操作 | `mutate/intent` | 走同一原生引擎与 permission |
| 撤销 | 原生 Ctrl+Z/历史 | `undo` | 原生 history 管内容，session timeline 记 actor 和回放句柄 |
| 交付 | 导出/发布 | `explain/handoff` | 记录来源、许可、成本和目标 |

## 6 · 当前建造顺序

1. 原标签扩展身份能力，删掉团队规则中的重复身份真相。
2. 接通团队状态、队长唯一性、群聊特殊会话和管理 Agent 边界。
3. 在原界面中完成 `@` 人/Agent/身份与 `/` Skill/命令/模板的一次迁移。
4. 在已落的 raw「全部文件」基础上补 Library 资产层、授权素材目录、类型过滤和文件整理写操作。
5. 按无限画布 → AIGC → 网页/文档 → 视频剪辑的依赖关系分别跑通最小闭环；顺序可因原生引擎审计调整，但不反向重做默认界面。

## 7 · 禁止重复的错误

- 不新建 `WorkbenchShell`、全局三栏 Stage/Inspector/Context 壳或全局 Action Ticker。
- 不新建第二套身份标签、团队 store、团队聊天库或团队控制台。
- 不通过点击模型图标、新快捷按钮或新子菜单提升队长。
- 不用一个通用 Inspector/通用 patch 强行解释设计、文档、视频和代码的内部结构。
- 不把“本地知识库”、“全部文件”和 Library 混成一个概念。
- 不在代码未实现时把目标态写成“已完成”。

# 10 · 当前项目接手梳理

> 用途：给后续智能体快速接手。先读本文件，再按文末阅读顺序深入。本文记录的是 **2026-06-16 当前真实状态**，不是未来目标。

## 1 · 一句话结论

Fleet 当前是 `app/` 下的 **craft-agents-oss 完整副本**，正在做中文桌面 Agent 工作台。首攻不是浏览器，而是 **终端 / 本机 CLI Runtime Host**：先完成 P0-B CLI 探测，再做 P0-C Runtime Catalog、P0-D Runtime Adapter。

## 2 · 绝对不要踩的坑

1. **不要重建 Electron/Vite/IPC 壳。** 直接改 `app/` 的 craft 结构。
2. **不要从红灯/黄灯项目复制源码。** 目前能直接迁移源码的只有 `craft-agents-oss` 和 `AionUi`。
3. **不要把 CLI 做成第二套会话。** 启动、输出、权限、停止、日志都要进入 craft `SessionManager` / `SessionEvent` / permission / timeline。
4. **不要把 CLI 自动检测放 onboarding 首页。** 自动检测在后台做；完整状态在独立 CLI 设置页；聊天页只放紧凑选择入口。
5. **不要把“检测到 CLI”说成“已能用 CLI 对话”。** 目前聊天页 CLI 选择只是 runtime intent，消息尚未路由到 CLI/ACP adapter。
6. **不要误判端口。** `electron:dev` 使用 `localhost:5173`。如果窗口显示 OmniVerse 或其它项目，先查 `lsof -nP -iTCP:5173 -sTCP:LISTEN`，确认不是别的 Vite 占端口。

## 3 · 当前运行方式

优先从仓库根目录运行：

```bash
./scripts/craft.sh run electron:dev
```

常用验证：

```bash
./scripts/craft.sh run typecheck:electron
./scripts/craft.sh run typecheck:all
./scripts/craft.sh run webui:build
./scripts/craft.sh run test:shared:all
```

本机曾出现过 `5173` 被 `/Users/lullwen/Documents/OmniVerse Vision_Codex/desktop` 的 Vite 占用，导致 Craft Electron 加载错误项目。处理顺序：

```bash
lsof -nP -iTCP:5173 -sTCP:LISTEN
kill <占用 5173 的非当前 app 进程>
```

如果 Electron 仍显示旧页面，再备份并清理 dev profile 的浏览器缓存；不要删除项目源码或用户配置：

```bash
profile="$HOME/Library/Application Support/@craft-agent/electron"
backup="/tmp/craft-electron-profile-cache-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
for name in "Cache" "Code Cache" "GPUCache" "DawnCache" "DawnGraphiteCache" "DawnWebGPUCache" "Service Worker" "Session Storage" "Local Storage"; do
  if [ -e "$profile/$name" ]; then
    ditto "$profile/$name" "$backup/$name" 2>/dev/null || true
    rm -rf "$profile/$name"
  fi
done
```

## 4 · 当前代码状态

当前 `app/` 工作区不是干净状态，包含多组未提交改动：

- P0-B CLI Runtime 探测：`packages/server-core/src/handlers/rpc/cli-runtime.ts`、`cli-runtime.test.ts`、协议 DTO/channel/routing、Electron channel map。
- CLI 基础 UI：`apps/electron/src/renderer/components/cli-runtime/CliRuntimePanel.tsx`、`pages/settings/CliRuntimeSettingsPage.tsx`、输入框中的紧凑 CLI popover。
- CLI 图标与缓存：`cli-runtime-icons.ts`、`cli-runtime-cache.ts`、`cli-runtime-models.ts`，使用 `@lobehub/icons`。
- `/` 命令和 `@` Skill 的短中文说明：`packages/shared/src/localization/`、`slash-command-menu.tsx`、`skill-mention-menu.tsx`。
- 其它遗留修改：`package.json`、`bun.lock`、`pi-agent-server`、多语言 locale、`claude-agent.ts` 等。后续智能体不要随意 revert，先确认是否属于当前任务。

重要背景：部分 UI 文件曾因误回滚导致状态丢失，后来从 `apps/webui/dist/assets/*.js.map` 恢复。接手时应以当前源码和测试为准，不要假设每个改动都已经过完整产品验收。

### P0-C Runtime Catalog

目标：把“自动探测快照”升级为可管理 runtime 目录。

建议文件范围：

- `packages/shared/src/protocol/dto.ts`
- `packages/shared/src/protocol/channels.ts`
- `packages/shared/src/protocol/routing.ts`
- `packages/server-core/src/handlers/rpc/cli-runtime.ts`

必须包含字段：

- `runtimeId`

优先参考 AionUi：

- `packages/web-host/src/agent-process-registry.ts`
- `packages/web-host/src/backend-launcher.ts`
- `packages/desktop/src/common/adapter/ipcBridge.ts`
- `packages/desktop/src/common/types/platform/acpTypes.ts`

必须接 craft：

- `SessionManager`
- `SessionEvent`
- permission request
- session timeline
- local-only RPC

### UI 修正只做接线，不重排

当前阶段只允许最小入口：

- 设置页：完整 CLI Runtime 管理。
- 聊天输入区：紧凑 CLI 选择；未选 CLI 时保持原 API 模型选择；选 CLI 后模型按钮显示 `Auto`。
- onboarding：首页不要出现 CLI 卡片。

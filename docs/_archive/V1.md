### 2026-05-29 · V1 UI 当前定稿经验

这几条是用户实际验收过的 UI 修复经验，接手 V1 时必须先看，避免继续“打地鼠”：

1. **白天模式黑块不是单纯背景问题**  
   如果浅色主题里出现黑色方块 / 黑色按钮阴影，先查 Textual 内置控件皮肤，尤其是 `Button.DEFAULT_CSS`。这次真正根因是 `Button.-style-default` 自带 `$surface` 背景和 `border-top` / `border-bottom: tall ...`，会在浅色主题里漏出黑色 raised button 效果。  
   修法：在 App 级 CSS 覆盖 `Button`、`Button.-style-default`、`Button.-style-flat` 的 normal / hover / focus / active 状态；消息操作按钮 `.msg-action-btn` 也要显式禁掉 `border`、`border-top`、`border-bottom`。

2. **边缘黑框要同时处理 Textual 与终端底色**  
   只改 `HomeScreen background` 不够。`App`、`Screen`、`HomeScreen`、`ChatScreen` 都要 `width: 100%; height: 100%; background: ${bg_base};`。dock 在顶部的 `#theme-badge` 必须 `width: 100%`，不要用 `1fr`。  
   同时在 `launch()` 进入 Textual 前先发 OSC 11 设置终端背景，再在退出时 reset，避免早期未绘制区域露出终端默认深色。

3. **输入框不要用透明下划线光标**  
   透明 + underline 的 cursor 在中文输入 / IME / 普通输入下容易显示成残留 `_` 或错位。当前稳定方案是块状光标：`background: ${accent}; color: ${bg_input}; text-style: none;`，并定义 `input--selection` 颜色。

4. **标题动画要从具体版本恢复，不要凭感觉重写**  
   2026-05-28 恢复标题动画时，可用 git/stash 依据是 `stash@{6}`（2026-05-27 09:00）里的 `click_pulse_logo.py` 与 `BeamLogo` 集成。22:46 的 commit 不包含这个未跟踪标题文件。标题 surface 的经验是：先找 git/stash/用户给的原型文件，再局部替换 `BeamLogo` / `click_pulse_logo.py`，不要重新发明动画。

5. **Textual 气泡布局的循环宽度依赖折叠 BUG (Vertical Chat Bubble Column Collapse)**  
   如果消息气泡（`.bubble`）设为 `width: auto`，而内部的文本 `.msg-text` 与操作栏 `.msg-action-row` 均设为 `width: 100%`，将产生循环宽度计算依赖，导致 Textual 布局引擎强行折叠气泡至 1 个字符宽的竖排文字。  
   修法：将文本 `.msg-text` 宽度设为 `width: auto;`（或不限），仅保留底栏 `.msg-action-row` 为 `width: 100%;`，这样父容器会自适应文本的实际物理排版宽度（最大不超过 58 字符），而底栏操作按钮则能撑满气泡并完美靠右对齐。

6. **异步原生跨平台文件选择对话框 (@work(thread=True))**  
   在 Textual 的主线程中如果直接同步调用系统底层的文件选取对话框（如 macOS 的 `osascript`、Windows 的 `powershell`、Linux 的 `zenity`），会彻底卡死 / 冻结 TUI 的 UI 动画以及光标渲染，甚至破坏与后端的 IPC。  
   修法：必须将系统级对话框的唤起包裹在 Textual 的 `@work(thread=True)` 异步工作线程中执行，通过 `self.call_from_thread` 调度 UI 更新或输入框文字追加，保证在弹出选档窗口时 TUI 依然能够流畅渲染动效。

7. **对错/撤回（✓ / ✗）的双向支持与回溯**  
   - 用户和 AI 的消息行气泡都要有对错按钮。对（`✓`）代表一键复制，错（`✗`）代表撤回。
   - 撤回逻辑上，AI 消息的撤回应该连同上一个用户 prompt 一起删除（毕竟是一对问答），并把该 prompt 文本重新放回输入框并 focus 聚焦，帮助用户无痛修改重新发送；用户自身消息的撤回同理。

8. **加号 + 上传按钮的位置对齐**  
   - 不能将 `+` 按钮随意丢在输入框旁边而显得凌乱。应该优雅地放置在 `#chat-ctx-row` 容器中（与右侧 token 提示条同一排高度的左侧），形成自适应宽度分布，以保持极简、高级的视觉层次感。

9. **验证命令**  
   UI 改完至少跑：
   ```bash
   uv run --extra dev pytest tests/test_tui_*.py -q
   uv run --extra dev pytest -q
   ```

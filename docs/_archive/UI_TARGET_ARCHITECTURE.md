# OmniVerse Vision · 客户端消费级设计（非当前桌面主线）

> 说明：本文是 OmniVerse 客户端设计资料，不是当前 Fleet craft 桌面基座的执行入口。当前桌面执行入口见 `docs/README.md`。

> 状态：**TARGET 设计单一真相**。目标：让**普通用户**也能像用手机 App 一样轻松、美观地把视频变成可读、可问、可导出的资产。
> 一套设计两端复用：**V1（Textual）只保留已验收视觉经验与必要 bugfix，V2（pi-tui）承接完整消费级体验**。视觉用 token 数据 `themes.json` 同源。
> 关联：[CLIENTS.md](CLIENTS.md)（客户端策略）、[V1.md](V1.md)（实测 UI 经验）、[V2.md](V2.md)、[ORCHESTRATION.md](ORCHESTRATION.md)（plan/evidence 数据来源）。

## 1 · 设计原则（面向普通用户）
1. **资产优先，不是聊天优先**：主线是「丢输入 → 看计划 → 跑 → 拿图文资产 → 问/导出」；聊天问答活在资产之上。
2. **诚实可见**：跑之前给 **AnalysisPlan 卡**（平台/有无字幕/要不要下载/预计时间·磁盘·成本/硬件够不够/降级路线）；跑之中给**实时管线进度**；隐私/离线/出网状态常驻。普通用户先放心再点「确认运行」。
3. **一套视觉语言**：四季主题（水墨宣纸，已重做）固化为 `themes.json` role token；每主题只一个 accent + 一个 laser 高亮，绝不混色。
4. **零学习成本**：一个输入框吃一切（链接/文件/截图）；F 键主功能；块状光标；✓/✗ 成对撤回；+上传在 ctx-row；Mimi 随状态变表情。
5. **薄消费者**：只走 REST/SSE，不嵌业务；后端隔离后从「进程内 import」切 REST，界面崩不拖垮任务。

## 1.5 · 终端硬约束（设计必须服从）
- **画布固定 120×30**（列×行）。30 行极紧：不做长滚动并列布局；四态是**同一屏内分态演进**，底部输入栏常驻，主体随阶段切换。
- **终端放不了真图**：关键帧用**可打开的引用**（`▣ 02:14 [打开]`），仅在支持 sixel/kitty/iterm 图协议的终端才渲半块缩略图（探测到才开，否则降级为引用）。"图文对齐"在终端=帧引用出现在正文对应时间处 + 可跳原片。
- **中文 2 格宽**：所有布局用 `string-width` 计算，禁用 `len()` 算宽（V1.md 已记此坑）。
- **键盘优先**，鼠标可选；truecolor 经 Textual；浅色边缘黑块/光标/气泡宽度坑见 V1.md 定稿经验，逐条规避。
- 资产态的「笔记 | 问答/证据」用 **70/46 分栏 或 F 键开关右侧 dock**，不强行三栏并列。

## 2 · 交互：四态主线（一屏内分态演进，底部输入常驻）
| 态 | 内容 | 数据来源 |
|---|---|---|
| **输入** | 大 logo + 一个输入框（贴链接/拖文件/截图）；下方常驻状态行：模型·VLM·隐私层·硬件档 | 本地 |
| **计划** | `/agent/intake` 检出媒体后弹 **AnalysisPlan 卡**：平台/字幕/下载/抽帧/预计时间·磁盘·成本/硬件/降级/是否需 Backend Browser Agent 或上传；用户确认、覆盖 skill/depth、取消 | `agent/intake` + `plan_analysis`（G1.5）|
| **运行** | 实时管线进度：probe→字幕/ASR→分段→抽帧→VLM→生成→导出，每步状态/耗时/降级原因；可取消（级联 kill）| SSE（G1）|
| **资产** | 左=带时间戳的**图文 markdown**（图片位置对时间、原片跳转、封面 Banner）；右=资产/证据面板 + **RAG 问答（答案带出处时间戳）** + 一键导出 Obsidian | export / evidence（G3）|

输入模态路由：贴**截图**只走 VLM 描述（跳过下载/ASR/抽帧）；贴**音频/播客**走 ASR 无抽帧；贴**视频**走完整流程。

## 3 · 功能清单（围绕 Asset Kernel，按 Gate 落地）
| 功能 | 依赖 Gate |
|---|---|
| 丢链接→图文笔记 / 丢截图→VLM描述 / 问视频（第几分钟·表情·音效·镜头，带出处）| G1 / G3 |
| AnalysisPlan 预览 + 成本熔断提示 + 硬件档/`oe doctor` 面板 + 离线开关 | G1.5 |

| 资产/证据浏览 + 跨视频检索 | G3 |
| 视频类型→配方选择（先显式 `profile=`，后可审计建议；安全/成本/隐私仍由 planner 决定）| G4 |
| 导出 provider：Obsidian（现有）/ Notion·飞书（目标）| G4 |
| Setup 向导补 Step 4-6（代理/VLM/ASR）| G1.5 |

## 4 · 配色系统（token 单一真相）
- 四季 × 日夜 = 8 套，每套固定 role token：`bg_base/panel/elev/input · text_l1-l4 · accent · border_subtle/strong · success/warning/error · user_bar/ai_bar · laser`。
- 导出 **`themes.json`** 作单一真相源；V1（Textual CSS 变量）、V2（pi-tui）、Web（pi-web-ui）都 import 它，改一处生效。
- 语义色专用：进度/计划/成本/降级各有固定语义色（不复用 accent），让「诚实可见」有视觉锚。
- 可读性门槛：正文/面板 ≥7、meta/底 ≥4.5、accent/底 ≥3；浅色禁纯白底、深色禁纯黑底（除秦汉玄黑契约位）。

## 5 · 落地拆分（V1 冻结 / V2 承接）
- **V1 现在只做**：已存在界面的 bugfix、兼容性修补、极小视觉锚点和测试锚定。不得在 V1 继续铺“四态主体验”、新主流程或 mock 外壳，避免把过渡界面变成第二套产品。
- **V2 承接完整体验**：四态 UI、`themes.json` 同源 token、Mimi 状态、AnalysisPlan 卡、资产/证据面板，都作为 V2 目标设计；只有当后端 Gate 提供真实数据后再接入。
- **随 Gate 接真数据**：计划态 ← G1.5 `plan_analysis`；运行态 ← G1 SSE；资产/证据/问答态 ← G3 EvidencePack；配方 ← G4。

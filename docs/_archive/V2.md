## 1 · 一句话定位
> **V2 = 一个预置 OmniVerse 感知接入的 pi Agent 客户端 + 一套复刻 V1 视觉经验的 pi-tui 界面。** 只走后端 REST/SSE，不嵌 Python 后端。

普通用户入口:

```bash
uv run ov                         # V2 TUI；若默认后端在线且用户未保存 mock/live 偏好，会自动 live
uv run ov serve --port 8000       # 启动共享 Python REST/SSE 后端
uv run ov --live --api-url http://127.0.0.1:8000
uv run ov v1                      # V1 Textual 兜底
```

`oe` 继续作为历史兼容 CLI；普通用户主入口是 `ov`。V2 启动层配置保存在 `~/.config/omniverse-vision/v2.json`；CLI flags 只做本次启动覆盖，不应覆盖用户已保存的 Setup 配置。未显式配置时，`ov` 会短暂探测 `apiUrl` 的 `/api/v1/health`：后端在线则 live，后端不在线才进入 demo/mock。

Backend Browser Agent 或外部工具可以把字幕交接写成 JSON 文件，然后在 V2 输入框粘贴:

```text
https://example.com/video :: ~/Downloads/ovv-handoff.json
```

也可以直接粘贴 handoff 文件路径；V2 会读取其中的 `source` / `url` 作为媒体源，并把 `subtitle` 或 `client_provided.subtitle` 转成后端现有 `client_provided.subtitle` 请求。JSON handoff 未声明字幕 `format` 时默认按 `srt` 处理；Bilibili JSON 字幕必须显式写 `"format": "json"`。

`URL :: handoff.json` 属于 client-provided 安全路线：V2 不会在 plan 前远程 probe 该 URL，而是用本地 handoff 构造最小 metadata 调 `/plan`，并把实际 `/analyze` 深度降为 `text_only`。这条路线用于绕过平台风控/版权限制下的字幕注入，不得退回“先抓远程再决定”。

## 2 · 核心思路：agent-native（比旧方案更优的关键判断）
旧方案把 V2 当「用 Ink 画几个屏 + 自写 ~300 行 agent loop 调 REST」。更优做法：
> **后端的 REST/SSE 是控制面真相，MCP 是 Agent 适配层；`pi-agent-core` 只负责客户端大脑与工具调用循环。V2 先消费 `/agent/intake`、`/plan`、`/analyze`、SSE、search/query/export 等稳定契约。**

- 当前 M0/M2 shell：用户输入链接/文件/handoff → V2 通过 REST transport 调 `/probe`、`/plan`、`/analyze`、SSE、recent tasks、chat/export 等现有后端端点；mock 模式清晰标注。
- TARGET M1 agent：用户输入「看看这视频讲了啥 + 链接」→ V2 先调用 `/agent/intake` 检测媒体引用 → `/plan` 生成可解释 AnalysisPlan → 用户确认/覆盖 → `/analyze` + SSE 跑任务 → search/query/frame/export 取证据 → 大脑(`pi-ai`)组织回答。
- TARGET agent loop：把「命令式」(intake/plan/analyze/export) 与「对话式」(问答) 统一成**一个 agent 循环**，不再像 V1 各写一套 Home/Chat/命令处理。
- 目标落地 ORCHESTRATION **模式 A**：**大脑在客户端(`pi-ai`)，后端只供感知工具**；当前 shell 不把后端 pipeline 复制进 V2。

## 3 · pi 包 → 职责映射（直接依赖，不自研）
| pi 包 | 提供 | V2 用它做什么 |
|---|---|---|
| `@mariozechner/pi-ai` | 统一多家 LLM API(OpenAI/Anthropic/Google/DeepSeek…) | 客户端「大脑」，取代自写 provider 适配 |
| `@mariozechner/pi-agent-core` | Agent 运行时 + 工具调用 + 状态管理 | agent 循环 / 工具编排 / Session，取代自写 loop |
| `@mariozechner/pi-tui` | 终端 UI 库，**差分渲染** | 渲染三屏，热切换主题不重启、CJK 宽度、真流畅，解决 V1 Textual 短板 |
| `@mariozechner/pi-web-ui` | AI 聊天 Web 组件 | 未来网页端同源复用，一套视觉两端跑 |

## 4 · 如何消费后端契约（不重复造管道）
- 后端 OpenAPI → 生成**类型化 TS SDK**；V2 / 未来 Web / V1-retrofit 共用同一 SDK，不各写 fetch。
- 长任务：`analyze` 返回 `task_id` → SSE(`Last-Event-ID` 重连) → 进度/结果；在 `pi-agent-core` 里把「等任务完成」建模为一个 **async 工具**。
- 也可直接把后端 **MCP server 作为 pi-agent-core 的工具源**(stdio/HTTP)，与 REST 二选一或并用——同一套感知工具，零额外封装。

## 5 · 视觉系统：一套主题，三端复用（单一真相源）
- 四季主题是**数据(token JSON)**，不是某端的代码。导出 `themes.json`(`THEMES`/`DAY_THEMES` + role keys)。
- V1(Python Textual)、V2(pi-tui)、未来 Web(pi-web-ui) 都 import **同一份 token**，改色一处生效。
- `pi-tui` 差分渲染 → 热切换主题不重启（解决 V1 execv 重启）；CJK 宽度用 `string-width`；真流畅。

## 6 · 参考 V1 的「功能 + 界面」（参考，非逐像素阻塞）
- **功能**：复刻 V1 可用流程——`agent/intake` / `plan` / `analyze`(URL→进度→结果) / search-query / `build-corpus` / `export`(Obsidian) / 任务历史 / setup 向导。后端能力一律走 REST/SSE。
- **界面**：复刻 V1 已验收的三屏(Home/Chat/Setup)、品牌(固定英文大标题 + 随语言副标题)、Mimi mascot、快捷键；复用四季 token。
- **避坑**：V1.md 的实测坑(Button 皮肤/OSC11 浅色黑块/光标稳定/气泡宽度/文件对话框 thread)逐条规避——用 pi-tui 的能力实现，不照搬 Textual 的 workaround。

## 7 · 顺带拿到的 Web 端
`pi-web-ui` 用同样组件模型 + 同一 token → 一套视觉，终端 + 网页两端跑，给非终端用户一个入口，不额外起项目。

## 8 · 为什么比旧方案好
| 维度 | 旧方案(ai-sdk + Ink + 自写 loop + 逐像素复刻) | 新方案(pi · agent-native) |
|---|---|---|
| Agent loop | 自写 ~300 行（造轮子） | `pi-agent-core`（成熟，工具调用+状态） |
| LLM 接入 | `@ai-sdk/*` 各家自己拼 | `pi-ai` 统一多家 |
| 渲染 | Ink | `pi-tui` 差分渲染（更强） |
| Web 端 | 无，另起项目 | `pi-web-ui` 同源复用 |
| 与后端关系 | 手写 fetch 调接口 | 类型化 SDK + 工具即 MCP，agent 驱动 |
| 复刻 V1 | 逐像素硬复刻（阻塞、重写炸弹） | 功能+视觉参考 + 共享 token（不阻塞） |
| 视觉真相源 | 各端各写 | 一份 `themes.json` 三端复用 |

## 9 · 顺序与里程碑（延后，但路线清晰）
前提：后端本地 REST→queue→Worker→SSE 纵切已通；V2 M0/M1 只做薄客户端接线，不接管 pipeline。
- **M0 transport**：类型化 SDK + 连 `/health /probe /analyze /tasks/{id}/events` 最小闭环。
- **M1 agent**：`pi-agent-core` 接入后端 REST/SSE SDK（intake/plan/analyze/search/query/export）+ `pi-ai` 大脑；CLI 跑通「丢链接出笔记」。
- **M2 视觉**：`pi-tui` 复刻三屏 + 导入四季 token + 热切换。
- **M3 web（可选）**：`pi-web-ui` 同源。

## 10 · 不做
不嵌后端；不在 G1/G2 前投入；不逐像素硬复刻当阻塞条件；不自写已被 pi 覆盖的 agent loop / LLM 适配。

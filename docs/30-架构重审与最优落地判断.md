> 状态日期：2026-06-22

## 0 · 一句话判断

**Fleet 是“人机共编一条时间线”的 AI 工作创作台。正确的统一层是 `session / SessionEvent / permission / actor / runtime 接入 + 结构化工具控制`，不是“一个万能 `DesignPatch` 管所有 surface”。** 每个创作面（设计/网页/文档/代码/视频/3D）用自己的原生文档模型和结构化工具，全部 emit 进 craft 的同一条 timeline、走同一套 permission、带同一套 actor 身份。设计面优先以 openpencil 的模型为研究对象，视频面优先以 OpenCut Classic 为研究对象；实际迁码须先获绿灯。所有外发执行（代码审查/生图/图转 3D/生视频/发布）统一成一个 External Execution / Job 模型。

这条判断同时修正了此前最大的两个架构错误：① 在"编辑 op"层强行统一（导致 artifact 编辑退化成 iframe 里 `executeJavaScript` 改 `element.style`，性能差、agent 难控）；② 把"外部审查"做成独立治理孤岛（应是 Job 模型的一个 type）。

---

## 1 · Fleet 是什么 / 不是什么（Q1）

是：人类主导、AI 辅助，在**一个软件、一条时间线**上完成真实生产闭环（开发/文档/PPT/设计/网页/AIGC/图片/视频/剪辑/审查/发布）。
不是：聊天工具（LobeHub 式气泡堆）、普通 IDE、Figma 克隆、独立剪辑器、审查控制台。

**当前方案是否服务这个目标？一半服务、一半跑偏。**
- 服务的部分：craft 的 session/timeline/permission/CLI-ACP 接入 = 真正把"人和 AI 在一条可审计时间线上共编"落地，这是别人没有的差异化。**这是 Fleet 的命，必须保留。**
- 跑偏的部分：① 重心一度滑向审查/治理面（已纠偏，见 `docs/01` §7）；② 编辑层用"万能 DesignPatch + iframe DOM eval"硬扛所有创作面——这是把"统一"放错了层。

## 2 · 脊柱判断：对在哪、错在哪、怎么改（Q2）

**对（保留）**：`SessionManager` / `SessionEvent`（一条 timeline）/ `permission` / `actor 身份(agentId·role·runtime)` / `runtime 接入(ACP·CLI·API)` / Action Ticker（事件流视图）/ annotations / automations / BrowserPane·CDP / Library 概念。这套是 Fleet 的承重墙，**不动**。

**错（推翻）**：把 `DesignAction`/`DesignPatch` 当成"所有 surface 通用的编辑 op 模型"。它的 `op` 联合想同时表达改样式、改代码、调视频，于是 applier 只能退化成"对 artifact 跑一段 JS 改 DOM"。**这是 over-unify——在错误的层统一。** 代码编辑要的是文件 diff，设计编辑要的是文档树节点操作，视频要的是轨道/片段操作，它们的**编辑 op 天生不同**，强压成一种只会让每种都做不好。

**改（下沉统一层）**：
- 统一**下沉**到 `SessionEvent + permission + actor`：任何面的任何编辑，最终都 emit 一条带 actor 的 `SessionEvent`、写动作前过同一个 permission 门。**统一在"发生了什么·谁干的·准不准·可不可回放"，不在"用哪种 op"。**
- `DesignAction/DesignPatch` **降级**：从"万能编辑 op"降为"通用动作信封"——只承载 `{actor, surface, 引用, 一句人类可读摘要, permission 结果, 指向某个面原生 patch 的句柄}`，**不再试图在 `op` 联合里穷举所有面的编辑语义**。各面的真实编辑由各面原生引擎做。
- `DesignEngine` **瘦身**：从"通用 patch 引擎 + iframe applier"瘦成"把面原生引擎的变更登记成 SessionEvent + 过 permission + 记 actor"的**桥**。它不再自己改内容。
- **选区**保留一个轻量跨面 `Selection 描述符`（喂 Inspector/Ticker 显示"现在选了什么"），但**重编辑状态归各面原生引擎**（如 openpencil 的 `SelectionManager`）。

## 3 · 分层：哪些共用、哪些分开（Q3）

| 层 | 共用 or 分开 | 内容 |
|---|---|---|
| **脊柱（共用）** | 全局唯一 | session、`SessionEvent` timeline、permission、actor 身份、runtime 接入、Action Ticker、动作信封 `DesignAction`、跨面 Selection 描述符 |
| **控制面（共用模式，按面实例化）** | 模式共用 | 每个面暴露一组**结构化 MCP/ACP 工具**给 agent（read/select/mutate/undo/explain/handoff），形状统一、内容按面 |
| **资产（共用）** | 全局唯一 | Library：媒体/组件/模板/字体/色板/动效/片段，带来源/许可/hash/version |
| **外发执行（共用）** | 全局唯一 | External Execution / Job 模型（见 §6） |
| **设计/矢量/UI 面（原生引擎）** | 分开 | **openpencil**：`PenDocument` 文档树 + `DesignEngine`(history/selection/variable/spatial) + `pen-mcp` 工具 |
| **代码面（原生引擎）** | 分开 | craft file diff + codegraph（结构索引） |
| **文档面（原生引擎）** | 分开 | craft 原生文档模型（craft 本就是"agent for Craft documents"，直接用） |
| **浏览器面（原生引擎）** | 分开 | craft BrowserPane/CDP（选择/标注/证据） |
| **视频/时间线面（原生引擎）** | 分开 | 以 **OpenCut Classic** 的时间线闭环为候选参考；新版 OpenCut 只研究 MCP/headless 方向 |

**原则**：共用"时间线/权限/身份/资产/外发/控制模式"，分开"各面的文档模型与编辑 op"。这正是"不孤岛"和"不强行一刀切"的平衡。

## 4 · 对 Agent 最容易控制的模型（Q6）

答案就是 **openpencil 的 `pen-mcp` 范式**，并推广到每个面。Agent 控制任何面，都给同一组**结构化工具动词**（不是让 agent 推 DOM selector + style 字符串、更不是截图找按钮）：

| 动词 | 设计面（openpencil 现成） | 推广到其它面 |
|---|---|---|
| **读结构** | `read_nodes`/`batch_get`/`snapshot_layout`/`find_empty_space` | 代码=符号/文件树、文档=块树、视频=轨道/片段表 |
| **选** | `get_selection` | 各面选区 |
| **改（结构化）** | `insert_node`/`update_node`/`move_node`/`delete_node`/`replace_node`/`import_svg` | 代码=文件 diff、文档=块编辑、视频=片段 op |
| **高层意图** | `design_skeleton`/`design_content`/`design_refine` | 各面的高层动作（如"重构此函数""把这段配音对齐") |
| **撤销** | `HistoryManager`（Ctrl+Z 级，足够；回滚保真只代码需要） | 各面 history |
| **解释/交接** | `get_design_md`/`export_design_md`、DESIGN.md | 各面导出/handoff |

Agent 控制的便捷度来自：**结构化文档模型可被读成 JSON、可被结构化工具修改、有 history、可导出解释**。这是 iframe DOM eval 给不了的。每个面照这六个动词出工具，agent 跨面的心智一致。

## 5 · 人类界面（Q7）

- **独立页先跑通**：设计画布、视频编辑器这种重交互面，先各自作为能跑的独立 Stage 模式验证（不必一开始就完美收进统一壳）。
- **最终收回统一壳**：收敛点在**壳层**——`Stage`（一个容器多模式）、`Inspector`（选区驱动、内容按面）、`Library`、`Action Ticker`。各面的原生引擎活在 Stage 模式内部，壳层统一。
- **不做**：为单功能开顶层页、把能力拆成一堆散按钮、为展示画线框图。

## 6 · External Execution Bridge：外发统一成一个 Job 模型（Q8）

代码审查、生图、图转 3D、生视频、剪辑渲染、发布部署、外部 AI 审查——**本质都是同一件事**：把一个任务派给外部 runtime/服务/站点，过 permission，跟踪状态，结果回到 timeline + Library。**统一成一个 Job 模型**：

```
Job { type, 输入引用(选区/文件/artifact), 目标(provider/runtime/site),
      permission(按敏感度定级), status, 结果(→Library/surface), 成本, provenance, 回放点 }
  └─ emit SessionEvent（带 actor）→ 一条 timeline · Action Ticker 显示 · 可授权可回放
```

- type 例：`code_review` / `image_gen` / `image_to_3d`(接 Blender MCP) / `video_gen` / `video_render`(opencut) / `deploy_publish` / `external_ai_review`。
- **当前的"External Review Center"降级为 Job 的一个 type（`external_ai_review`）**，收口掉它的独立治理孤岛叙事。ProjectPack/secret-scan 是这个 job 的输入预处理步骤。
- 这样浏览器登录态、外发权限卡、成本/隐私记账只在 Bridge 一处实现，所有外发能力复用。

## 9 · 更好的整体架构（数据流，非线框）

```
  人类 UI 操作 ┐                                        ┌ 设计面: openpencil(PenDocument+engine+pen-mcp+history)
              ├─ 结构化工具/动作 ─┐                      ├ 代码面: craft file diff + codegraph
  AI(ACP/CLI/API) ┘               │                      ├ 文档面: craft 文档模型
                                  ▼                      ├ 浏览器面: BrowserPane/CDP
                    ┌──────────────────────────┐  驱动   ├ 视频面: opencut
                    │  脊柱(唯一)               │◀───────┤ 活网页面: openui
                    │  permission 门 + actor    │  各面    └ (新面=注册原生引擎+一组结构化工具)
                    │  → SessionEvent(一条timeline) │ emit 进来
                    │  → Action Ticker / 回放   │
                    └──────────┬───────────────┘
                               │ 外发
                               ▼
                External Execution Bridge (Job 模型)
       review / image_gen / image_to_3d(Blender) / video / deploy / external_ai_review
                               │ 结果
                               ▼
                     Library(资产) + 对应 surface
```

一句话：**一条脊柱在中间，各创作面是挂在脊柱上的原生引擎（用结构化工具被人和 AI 共同驱动），外发统一走 Job 桥。** 不是"一个 DesignPatch 打天下"，也不是"每个场景一个孤岛 app"。

## 10 · 更短、更稳的落地顺序（Q9）

1. **脊柱瘦身（小重构）**：把 `DesignEngine` 收成"面变更→SessionEvent+permission+actor"的桥；`DesignAction/Patch` 收成动作信封。删除 iframe-eval applier 与半截 `design_tool` 的死路。**先止血，避免在错抽象上继续叠。**
2. **设计面 re-base 到 openpencil（下一刀主体）**：vendor `pen-core`/`pen-engine`/`pen-types`/`pen-renderer`，接 `pen-mcp` 作为 agent 工具、`pen-acp`/`event-adapter` 把引擎事件映射进 craft `SessionEvent`+permission。人和 AI 用**同一组结构化文档操作**共编一个真实设计文档，history 撤销。**这是"创作台真能创作"的第一块硬证据。**（集成点待实现验证）
3. **External Execution Bridge（Job 模型）**：先把现成的 External Review 收口成一个 job type，再加 `image_gen`/`image_to_3d`(Blender)/`deploy` 两三个 type 验证模型通用。
4. **代码面 + 文档面**（craft file diff / craft 文档模型 + 各自结构化工具）：低成本 breadth 证明"同一脊柱跨面"。
5. **视频面**：opencut 抽取，作为 Timeline Stage 模式（M2 一等，见 `docs/01`）。
6. **Library 统一** 跨面资产。
全程：治理面（审查/记忆/决策）保持收口。

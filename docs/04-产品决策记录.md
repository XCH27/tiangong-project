## 2 · 战略与顶尖增量（**待你拍板**，我的建议）

这些不是已定决策，是要冲"世界顶尖"建议尽快定的（执行难点登记、防跑偏说明、以及"怎么让软件少更新"的适配层架构，见 `docs/07-难点清单与更新韧性.md`）：

1. **分叉策略（需你拍板）。** 硬分叉 vs 软分叉未定，而"去 Craft 化"(改包名/协议/数据目录/全量中文)会逼你选——**全量改名 = 事实硬分叉**，之后难合 craft 上游(它仍活跃)。**我建议软分叉**：核心包名/协议先不动，品牌只做在用户可见层，增量放独立 package，定期合上游。深度去 Craft 化压到你确定不要上游之后。
2. **评测 + 可观测已经进入 D9 路线。** 后续还要把任务成功率、回归门禁和失败聚类补成正式评测体系；当前先从 token/cost/context/review trace 面板落地。
3. **顶尖缺口（列入 P2/P3）。** craft 实测**没有**：computer-use（截屏/点击/视觉操作软件）、容器级沙箱（跑不可信代码）、agent 语音/多模态输入。

## 3 · D4 设计要点（合法多账号 + 其他 CLI 历史归集）

- **凭据 Profile**：每个合法账号一份独立 profile（各自 auth / 历史 / 配置），"激活 = 切指针、**绝不删**"→ 不丢记录。craft 已有基础：`auth/state` + 加密 `credentials.enc` + chatgpt-oauth/claude-token。
- **不退出就能切**：**每个会话注入各自凭据 / HOME（路径隔离）**，而非改一个全局文件 → 不同账号可并行、互不踩。
- **其他 CLI 历史归集**：每个 CLI 一个**只读 adapter**（`~/.claude`、`~/.codex`、Grok 等多为 JSONL/SQLite），汇成统一可搜索浏览器；**只读、绝不写其库**、容错版本化；这些历史可喂给语义记忆(D2)。
- 时序：**非首攻**（首攻是 D3 终端 / CLI Runtime Host）。本节作为后续阶段的设计锚。

## 1 · 产品本体（一句话）

**Fleet 是一个"AI 工作创作台"：基于 Craft Agents，让人类主导、AI 辅助，在同一个软件里完成真实生产流程（软件开发 / 内容创作 / AIGC），而不是把一堆 AI 工具拼进一个壳。**

它把这些场景需要的能力——画布、时间线、属性面板、素材库、版本记录、AI 指令、导出——收进**一个结构化工作台**，让工作端到端发生在软件内部，而不是散落在桌面、浏览器和外部软件之间。多场景不是多软件，是同一工作台的不同配置（完整产品定义与统一交互模型见 **`docs/02-统一创作台与交互模型.md`**）。

判断任何功能要不要进主产品，只有一个标准：**它是不是"人机在同一条时间线上、用同一套动作共编"这个命题的承重墙。** 是承重墙的进核心；其余都是挂在主干上的下游能力，必须排队。统一输入路由、各类 Stage 模式（Code/Canvas/Timeline/Board）也都建在同一条主干上，不为某个场景另起一套。

## 2 · 一条主干（The Spine）

所有功能都挂在下面这一条主干上。这条主干是 craft 已有的东西的延伸，不是新发明：

```
                     ┌──────────────────────────────────────────────┐
   人类 UI 操作 ─┐   │  统一动作通道                                  │
                 ├──▶│  Action → (permission) → Patch → SessionEvent │──▶ 同一条 timeline
   AI 工具调用 ─┘   │  每个动作都带: actor / agentId / surface /     │     （可见·可审批·
                     │  selection / payload / 权限结果 / 回滚点      │      可回放·可回滚）
                     └──────────────────────────────────────────────┘
```

主干由四块承重墙组成。当前 `app/` 已重置为干净基座，四块都要按顺序重新落地：

1. **接入层 · CLI Runtime / ACP Host**（M0 第一批重做）
   把本机各家 CLI（Grok/Hermes/OpenCode/custom + 未来 Gemini/Qwen）和 API 模型统一接进 craft `SessionManager`。这是"接入算力"的地基。完成后收口，不再反复改。

2. **动作层 · `Action → Patch → SessionEvent` 引擎**（承重墙 · 当前最该补）
   人点鼠标和 AI 调工具，产出**同一种** action，走**同一条** permission → patch → timeline → rollback。
   现状：设计修改还只是 iframe DOM 临时 mutation + 摘要，刷新即丢，没有真正的后端引擎。**这是卡住整个设计工作流和多 Agent 共编的真瓶颈。**

3. **画布层 · Stage（浏览器 + Artifact 两块画布）**（待在新基座落地）
   - 浏览器 docked 进主工作台，是设计工作流"第一块画布"：真实网页上选择/框选/标注/证据。
   - Artifact Studio 是"第二块画布"：只对 Fleet/Open Design artifact 或本地 editable preview 开放编辑。
   - 两块画布**共用同一套选区与动作**——这是"不孤岛"的根。

4. **协作与记忆层 · 管理 Agent + 项目 Agent + 分层记忆**（纸面，未建）
   一个常驻**管理 Agent**管软件本身（状态/设置/记忆/权限/上下文/跨项目自动化），一套**项目 Agent**（队长/代码/设计/审查/测试/上下文）管具体执行；所有 agent 动作进同一条 timeline、带身份、可授权、可回放。详见 `docs/17`。

主干之上，所有"用量/成本/审查/打包"都收敛成一个**上下文效率 / 审查中心**（详见 `docs/16`），所有"记忆"都收敛成一套**分层记忆**（详见 `docs/05`）。

## 3 · 反"堆按钮"的合成纪律

用户的核心顾虑是"别把同类能力堆成一堆散按钮"。合成原则就是五个"唯一" + 一个"挂槽三问"：

**五个唯一（同类能力必须收敛成一个）：**

1. **一套选区模型**（`DesignSelection`）：浏览器选三块卡片、Artifact 选三块、Figma 选三个 node —— 进**同一个**选区集合，不是三套。
2. **一套动作模型**（`DesignAction`）：人和 AI 产出同一种 action，走同一条 patch/timeline/rollback。**不允许"人类 UI 一套 state、AI 工具另一套"。**
3. **一个 Inspector**：由"当前选区"驱动，与选区来自哪个画布无关。
4. **一个用量/审查中心**：session token、打包 token、压缩前后、外部审查节省，全进**同一个**面板，真实/估算/未知三色区分——不是每个功能各挂一个用量小组件。
5. **一套浏览器栈**：craft 的 BrowserPane/CDP/`browser_tool` 同时承载"人类标注 + 设计选择 + 外部审查提交"，**不为每个功能新起浏览器运行时**。

**挂槽三问（加任何功能前必须回答）：**

- 它挂在哪个 **Surface** 的哪个槽？（Conversation / Stage / Inspector / Context / Action Ticker，见 `docs/18`）
- 它用哪套 **选区 / 动作**？（必须是上面的统一模型）
- 它产生的变更怎么进 **timeline、怎么授权、怎么回滚**？

答不上来 → 这个功能切错了（要么 Surface 划分错，要么它其实是另一个功能的状态），不是少了个按钮。

## 4 · 三大能力域：怎么合成一个完整模块

下面把散落在多篇文档里的能力，按"一个域 = 一个完整模块"重新讲清楚。

### 4.1 设计工作流（一个画布管线，不是孤岛 Figma 克隆）

一条从"看网页找灵感"到"导出/交接"的管线，全部复用主干的选区 + 动作 + timeline：

```
浏览器画布(看真实网页) ─选区/标注/证据─▶ AI 上下文
        │                                      │
        ▼                                      ▼
Artifact 画布(编辑 AI 生成的网页/APP/PPT/商品页)
        │  └ Inspector: 文本·布局·外观·效果·字体·颜色·动效
        │  └ Library: 媒体/组件/模板/字体/色板/动效（拖入画布）
        ▼
DesignAction → DesignPatch → SessionEvent（人和 AI 共用，可回放可回滚）
        │
        ▼
Handoff: 导出 HTML/CSS · 让 AI 整理实现 · Figma(官方 API) · Stitch(prompt lane)
```

**先后顺序（关键判断）：**
1. 先建**动作引擎**（主干第 2 块），否则一切编辑都是假的。
2. 再把**浏览器 docked** 成第一画布（最便宜的真实验证场景）。
3. 再用 **open-design**（绿灯）引擎把 Artifact Studio 从 preview-only 升级成真正 committed patch。
4. 之后才是字体/颜色 → Library → Motion preset。
5. 最后才是 Figma/Stitch bridge。

**明确不做**：完整 Figma 克隆、完整视频剪辑器（NLE）、完整动画时间线。字体/颜色/动画是"网站/APP/PPT/商品页编辑的基础能力"，不是独立视频软件路线；动画只做 CSS/WAAPI/SVG/Lottie preset，不自研 Kdenlive/Premiere 级别。

### 4.2 上下文效率 / 审查中心（一个中心，不是七个散功能）

repomix、markitdown、codegraph、rtk、headroom、context-mode、外部 AI 审查——这些**不是七个按钮，是一条管线的不同环节**，由管理 Agent 统一驱动（详见 `docs/16`、`docs/17`）：

```
打包(repomix式) ─┐
转换(markitdown式)├─▶ ReviewBundle(含 hash/文件清单/secret scan/license 风险)
代码图谱(codegraph)┘         │
                            ├─▶ Context Optimizer(rtk压输出 + codegraph替整文件 + Reasonix稳定前缀 + headroom可选sidecar)
                            ├─▶ Usage/Token Report(真实/估算/未知三色)
                            └─▶ 外部 AI 多平台审查(用户授权浏览器登录态 → 归一化 ReviewReport)
                                        └ 每次外发: 目标平台·包大小·secret·成本·隐私 → 权限卡
```

一个入口、一条管线、一份成本账本。真实 token / 估算节省 / 外部平台成本必须分开标注；"网站不消耗 Fleet API token" ≠ "免费"。

### 4.3 Agent 协作（管理 Agent + 项目 Agent，不是一堆聊天气泡）

craft 目前没有成熟多 Agent。Fleet 的多 Agent **不是多个聊天框**，而是（详见 `docs/16`）：

- **管理 Agent（常驻 · 软件管家）**：管软件状态、记忆、设置、权限、上下文、任务入口、跨项目自动化（含调用 4.2 的审查中心）。默认**低上下文足迹**：只知道有哪些项目/各自阶段/用户长期偏好/可用能力，不读每个项目全部代码；被需要时才深入。
- **项目 Agent（按职责）**：队长 / 代码 / 设计 / 审查 / 测试 / 上下文 Agent，负责具体项目执行。
- **自动决策（分级授权）**：默认关键动作问用户；开启后管理 Agent 按记忆/偏好/规则在低风险场景代答，但分级——只读自动 / 低风险本地按偏好 / 写文件运行命令需规则授权 / 删除发布付款登录敏感必须明确确认。每个自动判断有依据、有记录、可回放、可撤销。
- 所有 agent 动作进**同一条 timeline**，带 `agentId/runtime/role`，权限按 Agent 分组，输出不混流。

## 5 · 五个常驻 Surface（功能挂在这里，不新开顶层页）

目标态 UI 单一真相见 `docs/18`。功能"挂进" Surface，不"新开 page"：

| Surface | 职责 | 挂什么 |
|---|---|---|
| Conversation | 对话 + 人类可读时间线 + 入口 | API/CLI 对话、模型/effort、技能/命令、附件、artifact 按钮、权限卡 |
| Stage | "动手"的工作面 | 浏览器（第一画布）、Artifact Studio（第二画布）、Figma/Stitch、Preview |
| Inspector | 选区驱动的精修 + 证据 + 交接 | Inspect / Comment / Library / Actions / Handoff |
| Context | 成本/用量/审查透镜 | 4.2 的审查中心：用量、打包、外部审查、压缩前后 |
| Action Ticker | 共编在场 + 回放 | 人/agent 动作流、权限事件、selection 变更、多 Agent 分流 |

记忆与管理 Agent 入口挂在 NAV Rail / Context；多 Agent 名册挂在 NAV Rail "在工作的智能体"。

## 6 · 开源项目：结合 vs 黑盒（精简版，详表见 `docs/14`）

**绿灯（已核准·可按归因迁源码）——真正该主动用起来的只有三个：**

| 项目 | 用来建什么主干件 | 状态 |
|---|---|---|
| **craft-agents-oss** | 主基座，直接改 `app/` | 在用 |
| **AionUi** | 多 Agent / Team / ACP / Skill 注入 / 进程生命周期 | **最被浪费的绿灯，多 Agent 该迁它** |
| **open-design** | Artifact Studio 的 manual-edit / live-artifact 引擎 | **Artifact 编辑别重造，建在它上面** |
| rtk / codegraph / DeepSeek-Reasonix / deepcode-cli | 上下文效率（压输出/代码图谱/稳定前缀）、Skill 路径 | 次要绿灯，4.2 里用 |

**黑盒（只学行为·不抄码）——近两个季度真正相关的只有两个：**
- **repomix**（ProjectPack 行为参考）、**markitdown**（格式转换行为参考）。

**研究货架（现在不是路线，别再每篇复述）：** headroom、openhands、browser-harness、openclaw、cloakbrowser、hyperframes、remotion、kdenlive、AstrBot、cherry-studio、cc-switch、warp、context-mode 等 ~20 项。它们是静态附录（`docs/14`），不占主线叙事。

**永不集成**：反检测/stealth 浏览器（CloakBrowser 类，与 D4 合法策略冲突）、绕用量/验证码/风控的任何能力。

## 7 · 落地序列（现在做 / 后面做 / 永不做）

把过去那张很长的 P1 清单重排成四个真实里程碑：

### M0 · 现在（建主干 4 件事）
1. **CLI Runtime 在干净基座上重做并验收** → 后端核心、catalog/test、Grok/Hermes/OpenCode/custom ACP、model/effort、附件硬拒绝、设置页、SessionManager CLI 发送分支已在 `work/integration-prep` 集成；聊天输入选择器最终产品化仍待接 Conversation UI（规格见 `docs/23-CLI-Runtime-重做规格.md`，验收见 `docs/24-CLI-Runtime-验收清单.md`）。
2. **真正的 DesignAction/Patch 引擎（server 端 + 持久化 + 回滚）** ← 契约、DesignEngine 状态机、`design_*` 事件、Agent actor、底部 Action Ticker 已在 `work/integration-prep` 集成；Stage 测试选区已能走真实 `DesignEngine.setSelection` 并驱动 Inspector / Action Ticker；选区与 patch 已落盘；Agent 写动作默认 `pending`，未授权不能 commit；`annotate` action 已复用 craft 现有 `AnnotationV1` 写入和回滚；`set_style` / `set_transform` / 文本替换已能生成可回滚 DOM/Artifact patch，并由 Workbench applier 路由；BrowserPane DOM writer 已接现有 BrowserPane `evaluate`，带 `browserPaneId` 的选区可实际 apply/revert。下一步是接 Artifact editable preview writer。
3. **BrowserPane docked 进 Stage** + 工具栏（选择/框选/标注/Comment/保存证据）+ 远程只读门禁。Stage route、Inspector、BrowserPane 原生 dock、单元素真实选区与后端矩形/视口批量元素选择已在 `work/integration-prep` 集成；选区→`AnnotationV1` 证据构造器和 annotate applier 已接后端，下一刀是把批量标注按钮、Comment AI 和远程只读门禁接到真实 action。
4. **Usage / Context Report v1**（只显真实 token，诚实标注）。服务、UI 组件、当前会话用量设置入口已在 `work/integration-prep` 集成；Usage Ledger + ProjectPack 已接入 Inspector Context tab；后端只读 ContextCenter overview 已把 Usage、Project Environment、context 工具、ProjectPack summary / dry-run preview 和 review readiness 收到同一个入口，并补齐 RPC 入参校验；不写 bundle、不外发。
5. **System Tools / Project Environment v1**：自动检测本机运行时、CLI Agent、搜索工具、sidecar、浏览器 helper 和项目环境，诊断 PATH/多版本/lockfile/venv 冲突；ProjectPack 和 Craft 已内置的 MarkItDown 文档转换已作为 bundled context capability 注册到统一 registry（详见 `docs/28`）。
6. **ProjectPack v1 / 审查数据层**：本地打包 + secret scan + token 估算 + dry-run + review prompt RPC 已集成；rtk/codegraph adapter、ProjectPack delta planner、外部审查 job 状态机、job 完成时本地保存 report 并回填 `reportId`、CLI Runtime 文本附件 policy 已进入 server-core 并接出 LOCAL_ONLY RPC；CLI Runtime 发送前已允许小文本附件并拒绝二进制/图片/PDF/office/audio/base64。Workbench Inspector「上下文」tab 与设置页已按四段式工作流展示 overview / delta / optimize / review readiness；External Review Center 已支持 bundle 关联 jobs/reports、可读 job 状态、多平台并排、severity/provider/文件/关键词筛选和人工粘贴归档（真实/估算/未知 token 与外部成本分色）。浏览器提交和自动回收仍是 M2。

### M1 · 紧接（用绿灯 OSS 在主干上长肉）
7. Artifact Studio 接 **open-design** 引擎，preview-only → 真正 committed patch。
8. **管理 Agent + 项目 Agent registry**：M0 已有只读 `agents:list/get`、内存 registry、session 查询、稳定 `manager:<workspaceId>` 与 `project:<sessionId>` actor，普通 API 与 CLI Runtime 事件开始带 `agentId/role/displayName/runtime`；manager agent 支持稳定 upsert 和 `lastActiveAt`。下一步再接 AionUi 进程生命周期 / Team / Skill 注入，不建第二套 session。

### M2 · 之后
9. 字体/颜色 → Library → Motion preset。
10. 外部 AI 审查自动化（接在 ProjectPack + Usage 之后）。
11. 分层记忆面板（`docs/05`）+ 管理 Agent 自动决策分级（`docs/17`）。

### M3 · 再之后
12. Fusion 多模型融合（D5，设置项默认关）、合法多账号 Profile（D4）、Figma/Stitch bridge。

### 地平线外（只参考，不排期）
视频导出（HyperFrames/Remotion/Kdenlive 边界）、多平台审查的复杂合并、完整 Figma/NLE。

### 永不做
反检测浏览器、绕用量/验证码/风控、自动注册账号、读 cookies/token、把私有项目默认外发。

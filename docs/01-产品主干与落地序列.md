# 01 · 产品主干与落地序列

> 状态日期：2026-06-22
> 作用：路线排序的单一真相。产品决策看 `docs/04`，架构裁决看 `docs/30`，当前代码状态看 `docs/00` 和 `docs/32`。

## 1 · 产品本体

Fleet 是一个 AI 工作创作台。它让人类和 AI 在同一个项目中完成开发、设计、文档、AIGC、素材处理、视频剪辑、审查、交付和发布，而不是把多个聊天工具或外部软件简单拼在一起。

不同场景共享项目、本地素材、Agent、记忆、权限、成本和时间线，但可以使用不同的工作面与原生编辑引擎。

## 2 · 正确的统一层

Fleet 不用一个万能 `DesignPatch` 统一所有内容格式。每个工作面使用自己的原生模型：

| 工作面 | 原生对象/引擎方向 |
|---|---|
| 无限画布/设计 | 结构化设计文档树、节点操作、选择、历史 |
| AIGC | 生成任务、输入资产、提示词、模型、成本、输出资产 |
| 网页/文档 | BrowserPane/CDP、文档块、文件 diff、Artifact |
| 视频剪辑 | 媒体资产、轨道、片段、关键帧、渲染任务 |
| 代码 | 文件、符号、diff、命令与测试 |

真正统一的是：

- craft session 与 `SessionEvent`；
- permission、自动决策分级和回放；
- actor / agentId / role / runtime；
- 六类通用工具动词：查看、选择、修改、撤销、解释、交接；
- 本地文件与 Library 资产来源；
- External Job、成本账本和导出记录。

`DesignAction`/`DesignPatch` 保留为动作信封和时间线桥，不承担所有工作面的内部文档模型。

## 3 · 防止功能散开的六个唯一

1. 一个项目与 workspace 真相。
2. 一个 raw file 入口“全部文件”，一个经过选择/授权/索引的 Library。
3. 一套 session、permission、timeline 和 actor 身份。
4. 一个统一输入区：`@` 找人，`/` 找 Skill/命令/模板；文件走附件与全部文件。
5. 一套 External Job：外部审查、生图、生视频、图转 3D、网页生成等都是不同 job type。
6. 一份真实/估算/未知分离的 token 与成本账本。

新增功能必须回答：挂在哪个工作面、操作什么原生对象、如何进 permission/timeline、如何撤销和交接。

## 4 · 产品结构

### 默认工作台

- 所有会话 / 全部文件；
- 会话即 Agent、稳定序号、模型/Runtime、身份标签和团队状态；
- 队长与团队群聊；
- “所有会话”层的常驻管理 Agent 专栏（右下角只作为可选唤起/最小化入口）；
- 设置、Skill、来源、本地知识库与系统工具。

### 四个专业工作面

1. **无限画布**：UI、网页、作图、分镜、素材编排、图片编辑。
2. **AIGC 生成**：生图、生视频、图生图、去背、扩图、图转 3D、角色资产和多阶段生成。
3. **网页/文档**：网站访问与标注、Markdown/文档/PPT/网页内容编辑；Agent 专用浏览器保留。
4. **视频剪辑**：剪辑视频、音频、字幕和 AI 生成的网页动画。

所有工作面共用“我的工作区” 与用户添加的本地素材目录。

## 5 · 建造顺序

### M0 · 协作与工具脊柱

1. 当前 action/session/permission 基础保持可运行。
2. 团队编排协议：会话即 Agent、队长、身份、状态、团队消息、任务和待审队列。
3. **RuntimeLane / TeamRun 协议冻结（D19）**：`AgentSeat` / `RuntimeLane` / `TeamRun` / `attributionChain` / `RunReport` / Bridge 错误码 / 文件租约类型冻结；CLI 队长可经 Fleet Bridge 跨 Runtime 编排 API 队员，但只发起受控 TeamRun，不直接调 API 队员工具。详见 `docs/38-API-CLI分离与跨Runtime团队编排.md`、`docs/33 §10`。
4. `@`/`/` 输入迁移与 Agent 说明同步。
5. 管理 Agent 最小入口、权限边界和跨项目概况。
6. 全部文件索引与 Library 资产契约。

### M1 · 创作面追上来

1. 无限画布最小闭环：人改一处、Agent 改一处、同一 timeline、可撤销。
2. AIGC External Job 最小闭环：提交、授权、进度、成本、结果自动入 Library。
3. 网页/文档最小闭环：选择、标注、编辑、保存与 Agent 工具等价。
4. Artifact 与设计引擎选择按 `docs/30`/`docs/31`，不继续扩 iframe DOM eval 死路。

### M2 · 媒体主线

1. 视频剪辑最小闭环：素材、轨道、片段、播放、裁剪、拼接、撤销、导出。
2. 网页动画渲染为视频/帧序列并进入剪辑。
3. Board/Compositor、字体/颜色、动效、组件与模板库深化。

### M3 · 外接与高级能力

- Figma/Stitch/API 交接；
- 合法多账号 Profile；
- 多模型融合 Fusion（D5 主干的 C4 高难度档，默认关闭，见 `docs/03`）；
- 外部发布和平台上传。

> 注：D5 主干里的 **Auto 路由 + 分层缓存 + 输入瘦身**（`docs/03`）是横切 API/OAuth 路径的能力，薄版可早做、不抢 M0 脊柱；只有 **Fusion 编排**硬留 M3。

## 6 · 当前冻结项

上下文效率、外部审查、记忆和决策面板只允许修 bug、归并和必要接线，不继续扩展独立治理中心。它们是管理 Agent 和创作流程的底层服务，不是当前产品重心。

## 7 · 源码参考原则

- craft-agents-oss 是主基座，AionUi 是团队/ACP/Skill 的绿灯来源。
- 设计、视频和生成式 UI 候选必须先按 `docs/14` 核许可证、技术栈和实际源码完整性。
- 许可证宽松不等于自动绿灯；用户明确核准并更新绿灯表后才能迁源码。
- 兼容或调用外部软件也可以是正确方案，不要求所有项目都拖进 Fleet 改造。

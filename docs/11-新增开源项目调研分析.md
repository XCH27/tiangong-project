## 2 · 深度解析与架构亮点

### 2.1 · DeepSeek-Reasonix
* **项目定位**：利用 Go 语言的高并发和单文件分发能力，打造的极简终端 AI 编码工具。
* **许可证结论**：MIT，已纳入 Fleet 绿灯表。可按需迁移 ACP/stdio、稳定前缀缓存、planner/executor、权限/沙箱、配置层等源码；接入必须走 craft session/permission/timeline。
* **主要亮点**：
  - **前缀缓存优化**：针对 DeepSeek 的 Prompt Cache 特性进行微调，避免长会话因 context 改变导致缓存失效，从而极大地节省 Token 费用。
  - **双模型协同运行**：支持将模型划分为 Planner (规划器) 与 Executor (执行器)，分别建立隔离、缓存稳定的会话环境。
  - **极简 JSON-RPC 插件体系**：将外部工具作为子进程通过标准输入输出进行 RPC，天然兼容 MCP。

### 2.2 · deepcode-cli
* **项目定位**：基于 Node.js 专门针对 DeepSeek-V4 推理模型优化的终端 AI 助手。
* **许可证结论**：MIT，已纳入 Fleet 绿灯表。可迁移 Skill 搜索路径、推理强度、MCP、权限配置、CLI/session 管理相关源码；不得另建第二套 session/config。
* **主要亮点**：
  - **Skills 跨客户端互操作性**：支持扫描多层级目录以识别 Skills：
    * 局部路径：`./.deepcode/skills/` 且兼融 `./.agents/skills/`
    * 全局路径：`~/.deepcode/skills/` 且兼融 `~/.agents/skills/`
    > [!TIP]
    > 这符合 `cc-switch` 推广的跨平台 Agent Skills 统一目录标准，Fleet 在管理本地/Workspace Skills 时应向这一扫描目录对齐。
  - **控制推理深度**：在配置中允许控制 `thinkingEnabled` 和 `reasoningEffort` (`max`/`medium`/`low`) 等，为推理模型定制了完美的系统级交互字段。

### 2.3 · AstrBot
* **项目定位**：打通多社交即时通讯软件 (QQ, Telegram, 飞书) 的 Agent 和 Chat 基础设施。
* **主要亮点**：
  - **Agent Sandbox (安全沙箱)**：
    * 代码执行和命令调用均在沙箱隔离环境运行，确保在自动执行任务时本机环境的安全性。
  - **智能会话压缩**：针对长文本会话，内置了自动截断与总结机制，维持窗口紧凑。
  - **庞大的插件生态**：拥有 1000+ 一键安装的社区插件，得益于其清晰的元数据和统一的 API。

### 2.4 · cockpit-tools
* **项目定位**：Tauri 框架开发的 AI IDE 账号管理及 Quota 同步控制台，为 `cc-switch` 的直接演进/分支版本。
* **许可证结论**：`src-tauri/Cargo.toml` 标注 `CC-BY-NC-SA-4.0`，非商业，红灯。只能黑盒学习状态总览、路径检测、实例/Profile 概念，不能复制源码。
* **主要亮点**：
  - **Antigravity IDE 的官方集成**：
    * 深入对接了 Antigravity 和 Antigravity IDE (Unified State Sync / OAuth / Keychain / Version checking)。
    * macOS Keychain / Windows Credential Manager 中写入的官方凭据名统一定义为 `gemini:antigravity` / `gemini:antigravityUnifiedStateSync.oauthToken`。
    * 说明了在 macOS/Windows 环境下通过命令行、快捷方式唤醒、版本检测 (支持 `>=1.21.6` 和 `<1.21.6` 的不同 Language Server 参数 `--random_port` 注入) 的精细流程。
  - **支持多账号隔离多开 (Instances)**：
    * 能够指定不同的实例目录 (`extra_args`) 开启多个独立的 IDE 进程，绕过单实例锁定。
  - **额度池与失败状态回填**：
    * 优化了 Quota 获取逻辑，在网络失败或 401 过期时将状态回存到本地数据库并发送状态广播通知，防止前端显示 stale 数据。

### 2.5 · RTK
* **项目定位**：本机 CLI 输出压缩代理，在命令输出进入 LLM 上下文前做过滤、分组、截断和去重。
* **许可证结论**：Apache-2.0，已纳入 Fleet 绿灯表。可迁移输出压缩、gain/discover 统计、hook 矩阵相关源码；未经用户确认不得自动安装全局 hook 或改写用户 shell/agent 配置。
* **主要亮点**：
  - **收益可观测**：`rtk gain` / `rtk discover` 能展示节省统计和遗漏机会，适合 Fleet 后续做“上下文效率”面板。
  - **跨 Agent hook 矩阵**：公开支持 Claude Code、Gemini CLI、Codex、Cursor、Windsurf、Cline/Roo、Kilo、Antigravity、Pi、Hermes、OpenCode、OpenClaw 等生态。
  - **边界清楚**：hook 主要改写 Bash/命令输出，Claude 内置 Read/Grep/Glob 等工具不经过 shell 的路径不会被它覆盖。

### 2.6 · context-mode
* **项目定位**：MCP server + hook，用沙箱工具和事件索引减少上下文污染。
* **主要亮点**：
  - **沙箱工具模式**：把大输出工具转为可编程执行和摘要返回，避免 raw data 直接进入上下文。
  - **会话连续性**：编辑、Git、错误、用户决策等事件进入 SQLite/FTS5，并通过 BM25 取回相关片段。
  - **可观测 UX**：`ctx-stats`、`ctx-doctor`、statusline 直接展示节省、诊断和上下文健康。
* **许可证结论**：Elastic License 2.0，不能复制源码、hook 配置或路由模板，只能黑盒学习产品边界。

### 2.7 · CodeGraph
* **项目定位**：本地代码知识图谱与 MCP server，让 Agent 用结构查询替代反复 Read/Grep。
* **许可证结论**：MIT，已纳入 Fleet 绿灯表。可迁移本地索引、结构化查询、MCP/installer 相关源码；接入必须提供本地数据删除/重建边界，不能索引未授权目录。
* **主要亮点**：
  - **预索引 + 自动同步**：项目内 `.codegraph/` 保存索引，文件变更后自动同步，避免索引 stale。
  - **减少易变上下文**：结构/调用链问题优先由图谱回答，减少整文件和长搜索结果注入，有助于稳定 prompt cache 前缀。
  - **多客户端安装经验**：Claude、Cursor、Codex、OpenCode、Hermes、Gemini、Antigravity、Kiro 等客户端的 MCP 写入边界值得黑盒学习。

### 2.8 · Open Design
* **项目定位**：本地优先的 Agentic Design 工作台，把现有 coding agent CLI 当作设计执行引擎，围绕 Skill、DESIGN.md、插件、artifact preview/export 组织工作流。
* **许可证结论**：根目录 `LICENSE` 与 `package.json` 标注 Apache-2.0，已纳入 Fleet 绿灯表。可迁移 runtime definitions、模型探测、prompt transport、stream parsers、Skill/Plugin/DESIGN.md/artifact/eval 相关源码；复制 templates/design-systems/skills/plugins 子目录前必须单独检查额外 LICENSE 和品牌资产边界。
* **主要亮点**：
  - **Runtime definition 层很完整**：`apps/daemon/src/runtimes/defs/*` 把 Claude、Codex、OpenCode、Hermes、Grok Build、Antigravity、Cursor Agent、Qwen、Qoder、Copilot、Kimi、Codebuddy、Reasonix 等拆成独立 definition。字段覆盖 `bin/fallbackBins/versionArgs/listModels/fetchModels/fallbackModels/buildArgs/promptViaStdin/promptViaFile/streamFormat/eventParser/reasoningOptions/authProbe/externalMcpInjection`，比 Fleet 当前的 CLI 探测清单更接近可执行 adapter catalog。
  - **模型列表策略更实用**：能 live probe 就 probe，失败回退 fallback；Grok 用 `grok models` 解析 `grok-*` 模型；Hermes/Reasonix 通过 ACP handshake 取模型；Codex 用 `debug models`；OpenCode 用 `opencode models`；Cursor 用 `cursor-agent models`；Antigravity 因无 `--model` 参数，走 settings.json 写入 + 锁的特殊策略。
  - **Prompt 传输策略很值得学**：它明确区分 argv、stdin、prompt file，避免 Windows / GUI 环境下 `ENAMETOOLONG` 与 PATH/shebang 失败。Grok Build 用 `--prompt-file`，OpenCode/Cursor/Qwen/Qoder/Copilot 多数走 stdin，Kimi 仍受 argv 长度限制。
  - **MCP 注入边界清晰**：按 runtime 声明 `claude-mcp-json`、`acp-merge`、`opencode-env-content` 等不同注入策略；这能补 Fleet 未来“CLI 选中后 MCP/Skill 怎么送进去”的设计缺口。
  - **Skill 协议兼容 Claude Code**：`skills/README.md` 与 `docs/skills-protocol.md` 明确一 folder 一 `SKILL.md`，并扩展 `od.mode/preview/inputs/parameters/outputs/capabilities_required`。这比 Fleet 当前 Skill 管理更接近“可视化、可筛选、可评测”的产品形态。
  - **Plugin manifest 有产品化层**：`plugins/spec/SPEC.zh-CN.md` 的 `open-design.json` 把 Skill、preview、inputs、pipeline、capabilities、evals 串起来，适合 Fleet 未来做插件市场和 Skill 安装规范时参考字段边界。
  - **DESIGN.md 系统适合补视觉质量**：`design-systems/*/DESIGN.md + manifest.json + design-tokens.json + components.manifest.json` 把品牌/组件/设计 token 变成 agent-readable 资产。Fleet 不该复制品牌系统，但可以学习“项目级设计约束文件”的形态，用于 UI agent 和网页点评。
  - **E2E/visual eval 覆盖面强**：`e2e/ui/*` 包含 visual workspace、settings、automation、critical smoke、diagnostics export、app restoration 等测试主题，说明 artifact/设计工作台要有视觉回归和诊断导出，不只跑 typecheck。
* **对 Fleet 的直接启发**：
  - CLI Runtime Catalog 不应只保存“是否安装 + 版本”，还要逐步扩展成 runtime definition：`promptTransport`、`streamParser`、`modelProbe`、`reasoningOptions`、`authProbe`、`mcpInjection`、`supportsResume`。
  - 当前 Grok/Antigravity/Hermes 的适配可迁移 open-design runtime definitions 的实现片段，但必须适配进 craft/Fleet 的 catalog、permission、timeline 和 local-only RPC。
  - Skill 管理应从“文件列表”升级为“Skill + Plugin manifest + eval + preview”的组合；P1 阶段可迁移 open-design 对应协议和服务实现。
  - 浏览器/网页点评和 artifact 预览可以迁移 open-design 的 sandboxed iframe + export + critique loop 产品模型；实际落点仍应复用 craft browser pane，不另起第二套预览运行时。

## 3 · 对 Fleet / Antigravity 研发的指导意义

> [!IMPORTANT]
> **许可证红线**：`open-design`、`rtk`、`codegraph`、`DeepSeek-Reasonix`、`deepcode-cli` 已进入绿灯表，可按限定范围复制源码并归因；`AstrBot`、`context-mode`、`cockpit-tools` 仍是红灯/高风险黑盒，不能复制源码、配置、测试、UI 或资源。

### 💡 核心设计参考点
1. **统一 API Quota 错误状态显示**：
   在 `PlanUsageCard` (API 模式) 中，获取 Quota 的请求若失败，应该把错误原因反映到页面状态，提示 "凭证失效/更新失败" 并提供重新同步或直接修改的“逃生舱”入口，这正是 `cockpit-tools` 在 1.0 版本对 Windsurf/Cursor 配额失败的处理思路。
2. **多模式排版隔离**：
   - 本地模型连接：不显示网络 Quota、不显示费用估算，只展示本地模型的免费特性和 tokens count。
   - 终端 CLI Runtime：展现当前 CLI 客户端登录状态，如异常提示在命令行中登录。
   - 线上 API / Token Plan：只显示配额进度条（如 5小时 / 7天 等进度）及费用估计，剔除冗余的“运行中/暂停/连接测试”等按钮。
3. **Skills 的标准化目录**：
   Fleet 的 Skill 注入 and 扫描可以优先兼容统一的 `~/.agents/skills/` 目录，便于未来支持从其它客户端一键互操作；这部分可从 `deepcode-cli` 迁移实现。
4. **缓存命中和上下文效率分层**：
   - REASONIX：可迁移稳定前缀、双模型/双会话和缓存友好的上下文组织。
   - RTK：可迁移命令输出压缩和节省统计，但默认不安装 hook。
   - CodeGraph：可迁移本地结构索引，减少 Read/Grep 和整文件注入。
   - context-mode：学习 `ctx-stats`/statusline/沙箱工具/FTS5 检索体验，但因 ELv2 只黑盒参考。
5. **Agentic artifact / 设计工作流**：
   - open-design：可迁移 Skill/Plugin/DESIGN.md/Artifact Preview/Eval 的组合方式，补 Fleet 当前“能执行代码任务，但缺少可复用视觉工作流和质量评测”的空白。
   - Fleet 应先把这些能力写成数据结构和接线表，不急于改 UI；等浏览器预览和网页点评恢复后，再把 artifact 预览、导出、点评接入同一 session timeline。

### 🧭 最新开源 Agent / CLI 候选更新

1. **Gemini CLI**：官方 Apache-2.0，并有 `gemini --acp` stdio JSON-RPC 模式。它是当前最合理的下一候选 mapping，但必须先做本机 opt-in smoke，不能因为开源就直接复制源码或自动恢复内置探测。
2. **Qwen Code**：官方 Apache-2.0，能力覆盖 Auto-Memory、Auto-Skills、SubAgents、Agent Teams、MCP、daemon/SDK/IM bot。当前 Fleet 仍先保持 unsupported，直到确认 stdio ACP 入口或完成 daemon adapter 设计。
3. **Cline / Roo Code**：Apache-2.0，适合学习 mode、custom modes、team/SDK/CLI 产品模型；未核准前只黑盒参考。
4. **OpenHands / Agent Canvas**：适合学习 local/remote/cloud backend、sandbox 风险、多 backend 切换和 automation，不适合作为单个 stdio runtime 直接接。
5. **ACP**：官方协议仓库 Apache-2.0，后续 Fleet ACP client 应按 `protocolVersion` 和 capabilities 判断能力，不能只按当前 fake ACP 契约硬编码。

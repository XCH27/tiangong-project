# 05 · 记忆系统方案（分级 · 全本地 · 可查可删）

> 对应决策 **D2**（见 `04-产品决策记录.md`）。目标：给"大管家"一套**全本地分级记忆**，长期个性化，对新手无感，且用户**可查、可删、可导出**。
> 边界：OpenClaw / Hermes 仅**黑盒借鉴思路**，不拷源码（非绿灯）。实现走**接口隔离**，写进 craft 现有 session/config 真相，不另起第二套。

## 1 · 四层记忆

| 层 | 是什么 | 存什么 | 生命周期 |
|---|---|---|---|
| **工作记忆** | 本会话窗口 | 当前对话 + 工具结果 | 随会话；craft 压缩已处理 |
| **情景记忆** | 近期会话的摘要与事件 | 每次会话结束蒸馏的"做了什么/结论/产物" | 数周；可检索、可衰减 |
| **语义记忆** | 长期事实与用户偏好 | 用户是谁、惯用栈、口味、长期目标、项目知识 | 长期；向量+关键词检索 |
| **程序记忆** | 怎么做某类事 | 复用流程 / 技能 / 惯例 | 长期；与 Skill 系统打通 |

## 2 · 三个动作

- **Promotion（提升）**：会话结束 → 蒸馏要点写入情景记忆；反复出现的事实/偏好 → 升入语义记忆。
- **Decay（衰减）**：久未命中的情景记忆降权/归档，避免噪声与膨胀。
- **Retrieval（检索注入）**：开新会话/新任务时，按相关度**检索少量**相关记忆注入上下文——**按需取片段，不塞满窗口**（与 craft 压缩、子智能体隔离配合）。

## 3 · 存储与隐私

- **全本地**：与 craft 同源目录（`~/.craft-agent`，去 Craft 化后随之改名）；SQLite 存结构化 + 本地向量索引（嵌入可本地/可选）。敏感项随 craft `credentials.enc` 加密。
- **用户主权**：一个"记忆"面板——可查看、搜索、**删除单条/清空**、导出。分级让"该记的记、敏感的可选不记"。
- **默认行为**：默认开启分级记忆（D2=2A）；可全局关闭；删除即真删。

## 4 · 与 craft 的关系（不重造）

- craft 已有：上下文压缩(309 处)、sources/session 持久化、`config/preferences`。记忆是其上的**增量层**。
- 接法：记忆读写走一层 `MemoryService`（server-core 内），输入/输出都映射到 craft `SessionEvent`/config，**不新建第二套 conversation/session store**。

## 5 · 落地阶段（非首攻；首攻是 D3 终端 / CLI Runtime Host）

| 阶段 | 目标 |
|---|---|
| Mem-1 | 工作+情景：会话结束蒸馏摘要落库，可检索 |
| Mem-2 | 语义：事实/偏好抽取 + 检索注入 |
| Mem-3 | 用户记忆面板：查/搜/删/导出 |
| Mem-4 | 程序记忆 ↔ Skill 打通；衰减与去重 |

## 6 · 验收要点

- 关掉记忆，行为回退到 craft 原样（接口隔离可验证）。
- 删除一条记忆后，后续检索不再命中它。
- 记忆注入是"少量相关片段"，不把窗口塞爆（与压缩协同）。

## 7 · 选型：自研 vs 克隆仓库（已对比）

你克隆的 5 个记忆项目，按"TS + 可视化管理 + 配对话"契合度对比：

| 项目 | 语言 / 许可 | 记忆模型 | 对 Fleet |
|---|---|---|---|
| **letta-code** | **TS** / Apache-2.0 | **可编辑记忆块** + `generate-memory-viewer`（记忆查看器）+ context-usage；记忆优先的 agent harness | **最贴近"直观可见可管理"**；TS，可借鉴/可绿灯化（需归因） |
| **supermemory** | TS / MIT | 记忆 API + Web UI | TS，有可视 UI，可参考 |
| **mem0** | TS+Py / Apache-2.0 | 记忆层（抽取/检索）+ OpenMemory **MCP** | 成熟，可作**引擎经 MCP/adapter 接**，不拷源码 |
| **CowAgent** | **Py** / MIT | **三层(context→daily→core) + Deep Dream 蒸馏 + 关键词+向量混检** | 思路极佳（**验证了本文四层**），但 Py → **黑盒参考** |
| **mempalace** | Py / MIT | 本地优先、逐字存、LongMemEval 跑分 | Py → 黑盒参考；本地优先理念可借 |

**建议：自研接口 + 原生 MVP（本文四层）；UX 抄 Letta 的"可编辑记忆块 + 记忆查看器"（最满足你"直观看到 + 方便管理"），分层/蒸馏抄 CowAgent。** 不把任何 Python 引擎 fork 进 craft（跨语言 + 违反绿灯规则）。若不想自建向量检索：在 `MemoryService` 接口背后**用 mem0（Apache、有 MCP）当检索引擎**，随时可换——既快又保持"接口隔离"（见 `07`）。

> 注：letta-code/supermemory 虽 TS + 宽松许可，但按 `AGENTS.md`，MIT/Apache ≠ 自动绿灯——要拷源码需先核准写进绿灯表 + 归因；先按**黑盒 / 模式借鉴**起步最稳。

# 05 · 分层记忆系统方案（分区 · 全本地 · 可查可删 · 管理 Agent 拥有）

> 对应决策 **D2**（见 `docs/04-产品决策记录.md`）。
> 定位：记忆不是"一个大池子 + 一个记忆功能"，而是**按归属分区分层**的体系，由**管理 Agent**（`docs/17`）拥有索引与生命周期，项目 Agent 按需读取。它和权限、时间线、上下文效率（`docs/16`）打通，是 `docs/01` 主干第 4 块的一部分。
> 边界：全本地、接口隔离，写进 craft 现有 session/config 真相，不另起第二套。letta-code/CowAgent/mem0 等仅黑盒借鉴思路或经 adapter 接入，不拷源码（非绿灯，见 `docs/14`）。
> 当前分支状态：**MVP 已落主线**——`shared/protocol/memory.ts`（7 分区 + 4 层 + 默认敏感度 + 隔离纯函数 `memoryQueryAllowed`/`memoryEntryMatches`）+ `server-core/services/memory-store.ts`（落 `<workspace>/.fleet/memory.json` 与 `~/.craft-agent/global-memory.json`，add/list/get/update/delete，scoped 分区按 scopeId 隔离，user/software 分区全局共享）+ `memory` RPC + 设置里的独立「记忆」页（按分区查看/新增/删除/启用禁用）+ 输入框记忆建议条（`MemoryInputSuggestions`/`useMemoryInputSuggestions` 接 `FreeFormInput`）。**已补**：TF-IDF + 3-gram 语义检索、episodic 时间衰减、会话结束 turn 事实抽取、管理决策依据注入、snippet/suggestion 服务。**未做**：向量库/更稳健抽取、归档 UI、L3 清空/导出确认、记忆 ↔ Skill 飞轮深度接线。

---

## 1 · 为什么要分区，而不是一个大池子

如果记忆是一个大池子，会立刻出现：软件级偏好和某个项目的细节混在一起、敏感项目记忆泄漏进别的项目上下文、删除和权限粒度无从谈起、检索注入要么塞太多要么取不准。

正确结构是**按归属分区 + 按时效分层**：分区回答"这条记忆属于谁"，分层回答"它该活多久、怎么衰减"。

## 2 · 七个记忆分区（按归属）

| 分区 | 存什么 | 谁拥有 / 谁读 | 默认 | 敏感度 |
|---|---|---|---|---|
| **用户长期记忆** | 用户是谁、惯用栈、口味、长期目标、重要判断、常用偏好 | 管理 Agent 拥有；项目 Agent 按需读 | 默认开 | 中（含偏好） |
| **软件状态记忆** | 有哪些项目、各自阶段、可用能力/Runtime/Agent/工具、软件设置 | 管理 Agent 拥有 | 默认开 | 低 |
| **项目记忆** | 某项目的目标、约束、规则、关键决策、产物、阶段 | 按项目隔离；该项目 Agent 读 | 默认开（按项目） | 中（项目私有） |
| **Agent 记忆** | 某 Agent 的角色配置、惯例、程序性技能、历史表现 | 该 Agent + 管理 Agent | 默认开 | 低 |
| **任务记忆** | 单个任务的目标、子任务、进展、结论、证据链 | 任务相关 Agent | 随任务；可归档 | 中 |
| **设计资产记忆** | 媒体/字体/色板/动效/组件/模板的来源、许可证、hash/version、可复用范围 | 设计 Agent + Library | 默认开 | 中（含许可证） |
| **外部审查记忆** | 提交过哪些平台、bundle hash、提交内容、成本、隐私风险、原始返回、归一化报告 | 管理 Agent（审查中心） | 默认开 | **高（含外发记录）** |

跨分区纪律：项目记忆**默认不互相可见**；管理 Agent 可在用户授权下把某条提取成"项目上下文"喂给项目 Agent，但要记录来源。外部审查记忆敏感度最高，外发内容/成本/隐私必须可审计。

## 3 · 四层时效（按生命周期，叠加在分区之上）

| 层 | 是什么 | 生命周期 |
|---|---|---|
| 工作记忆 | 本会话窗口（对话 + 工具结果） | 随会话；craft 压缩已处理 |
| 情景记忆 | 近期会话/任务的摘要与事件 | 数周；可检索、可衰减 |
| 语义记忆 | 长期事实与偏好（升入用户/项目/Agent 分区） | 长期；向量 + 关键词检索 |
| 程序记忆 | 怎么做某类事（复用流程/技能/惯例） | 长期；与 Skill 系统打通 |

## 4 · 生命周期（管理 Agent 维护）

管理 Agent 负责所有分区的索引与生命周期，四个动作：

- **Promotion 提升**：会话/任务结束 → 蒸馏要点写情景记忆；反复出现的事实/偏好 → 升入对应分区的语义记忆。
- **Decay 衰减**：久未命中的情景记忆降权/归档，避免噪声膨胀。
- **Retrieval 检索注入**：开新会话/任务时，**按相关度取少量片段**注入，不塞满窗口（与 craft 压缩、子 Agent 隔离、`docs/16` 上下文效率配合）。
- **Lifecycle 治理**：保留 / 归档 / 删除 / 提取成项目上下文——这是管理 Agent 的核心职责，可在自动决策下做 L0/L1（归档草稿、整理），但**删除（L3）必须用户确认**。

## 5 · 默认开关与权限分级

| 动作 | 默认 | 等级（对齐 `docs/16` 自动决策） |
|---|---|---|
| 读取记忆注入上下文 | 自动 | L0 |
| 写情景/语义记忆、归档、整理 | 开启自动决策后可自动 | L1 |
| 提取项目记忆 → 喂给另一个项目 Agent | 需授权 | L2（跨项目，记来源） |
| 外部审查记忆写入（外发记录） | 随审查流程，外发本身要确认 | L2/L3（看内容敏感度） |
| **删除记忆分区 / 清空 / 导出敏感记忆** | **必须明确确认** | **L3** |

用户主权：一个**记忆面板**——按分区查看、搜索、删除单条/清空、导出。分区让"该记的记、敏感的可选不记、项目的归项目"。删除即真删。

## 6 · 怎么接进 craft（不重造）

- craft 已有：上下文压缩、sources/session 持久化、`config/preferences`、`credentials.enc`。记忆是其上的**增量层**。
- 接法：记忆读写走一层 `MemoryService`（server-core 内，RPC 默认 `LOCAL_ONLY`），输入/输出映射到 craft `SessionEvent`/config，**不新建第二套 conversation/session store**。
- 存储：全本地，与 craft 同源目录（去 Craft 化后随之改名）；SQLite 存结构化 + 本地向量索引；敏感项随 `credentials.enc` 加密。
- 与上下文效率打通：检索注入要和 `docs/16` 的 Context Optimizer 协同——记忆摘要进"半稳定层"，保持 hash 稳定以利缓存命中；不要把整段记忆塞进稳定前缀。
- 与权限/时间线打通：写入/删除/跨项目提取都走 permission + timeline，可回放可回滚（对齐 `docs/16` 自动决策的"有依据、有记录、可撤销"）。

## 6.1 · 记忆驱动的输入建议（合并自原 `docs/08`）

输入框上方一行，两类可点建议，直接复用本记忆库（D2）：

1. **记忆建议**：按分级记忆 + 历史对话，匹配用户常说的话 / 常用提示词浮出几条。来源 = 记忆层语义检索（高频句 = 高频语义记忆）。
2. **快捷用语（snippet）**：用户自定义触发词 → 展开内容。例：输入 `转3d` → 浮出预设的几条生图提示词，点了把全文填进输入框。数据 = 本地 `snippets` 表 `{触发词, 候选展开[], 标签}`，用户可增删改；前缀/关键词触发，多候选列出来选。

落点：renderer 输入框组件 `FreeFormInput.tsx` + `MemoryInputSuggestions.tsx` + `useMemoryInputSuggestions.ts`，后端 `SuggestionService`（读记忆检索 + snippets 表）。snippets 写进 memory.software 分区（`snippet:JSON`）、记忆走记忆库，**不另起第二套真相**；当前实现通过 `listMemory({partition:"software", contains:"suggestion:<query>"})` 返回最多 5 条建议（snippet 优先 + 语义记忆）。

## 7 · 落地阶段（挂在 `docs/01` 主干上，M2）

记忆**不抢在主干前面**。顺序：

| 阶段 | 目标 |
|---|---|
| Mem-1 | 工作+情景：会话/任务结束蒸馏摘要落库，可检索；先做软件状态 + 用户长期 + 项目三个核心分区 |
| Mem-2 | 语义：事实/偏好抽取 + 检索注入；接 `docs/16` 半稳定层 |
| Mem-3 | 用户记忆面板：按分区查/搜/删/导出；删除走 L3 确认 |
| Mem-4 | 管理 Agent 生命周期治理（归档/提取/衰减）+ 设计资产/外部审查/任务分区 + 程序记忆 ↔ Skill 打通 |

## 8 · 验收要点

- 关掉记忆，行为回退到 craft 原样（接口隔离可验证）。
- 删除一条记忆后，后续检索不再命中它（L3 确认 + 真删可验证）。
- 项目记忆默认不串区：A 项目记忆不会无授权出现在 B 项目上下文。
- 记忆注入是"少量相关片段"，不把窗口塞爆（与压缩 + Context Optimizer 协同）。
- 外部审查记忆能完整回放外发内容、平台、成本、隐私风险。

## 9 · 选型：自研 vs 克隆仓库（黑盒参考）

| 项目 | 语言 / 许可 | 借鉴点 | 对 Fleet |
|---|---|---|---|
| **letta-code** | TS / Apache-2.0 | 可编辑记忆块 + 记忆查看器 + context-usage | UX 抄"可编辑记忆块 + 记忆查看器"；TS 但未绿灯，先黑盒 |
| **CowAgent** | Py / MIT | 三层(context→daily→core) + 蒸馏 + 关键词+向量混检 | 验证了分层/蒸馏思路；Py → 黑盒 |
| **mem0** | TS+Py / Apache-2.0 | 记忆层 + OpenMemory MCP | 可作引擎经 MCP/adapter 接，不拷源码 |
| supermemory / mempalace | TS·Py / MIT | 记忆 API/本地优先 | 黑盒参考 |

**建议**：自研 `MemoryService` 接口 + 原生 MVP（本文分区 + 分层）；UX 抄 Letta 的记忆查看器，分层/蒸馏抄 CowAgent。不把任何 Python 引擎 fork 进 craft。若不想自建向量检索，可在接口背后用 mem0（Apache、有 MCP）当可换引擎，保持接口隔离（见 `docs/07`）。

> 注：letta-code/supermemory 虽 TS + 宽松许可，但 MIT/Apache ≠ 自动绿灯（`AGENTS.md` 规则 17）——拷源码需先核准写进绿灯表 + 归因。先按黑盒 / 模式借鉴起步。

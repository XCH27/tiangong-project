## 1 · 真实目标（修正后）

craft 已经能让 **Agent** 选元素、截图、区域裁剪、(给自己)标注。Cursor/Codex 式"网页点评"对 Fleet 缺的是**人类**这一侧：让**用户**也能在一个**停靠在聊天右侧的浏览器面板**里，**主动**开/关、**鼠标点选**元素、**框选多个元素**、**多选后一起批注或编辑**、**手画标注**、一键截图，并把这些**人产生的证据**送进 session timeline 给 Agent 用。

这也是 Fleet 设计工作流的第一块画布：普通网页先支持“选择 + 证据 + 注释 + Agent 指令”，Fleet/Open Design 生成的 artifact 再支持 Artifact Studio 的手动微调、文字/字体/颜色编辑、动画编辑和语义拖动/重排。所有动作都必须能被 AI 复现：用户框选、拖拽、裁切、换字体、调色、加动画、调参时产生 `DesignAction`；AI 要改同一组选区时也提交 `DesignAction`，而不是走单独的 DOM 注入或鼠标自动化暗管。

## 2 · craft 现状（实测纠正，别再误判）

craft 已有一套成体系的内置浏览器，**由 `browser_tool` 驱动**（内置 Chromium）：

| 已有能力 | 形式 |
|---|---|
| 开 / 导航 | `browser_tool open`（默认**后台**，`--foreground`）、`navigate` |
| **选元素** | `snapshot` 取可达性元素 + refs（`@e1`…）、`find <query>` 按词缩小 |
| 交互 | `click` / `fill` / `select`（用 ref） |
| **截图 + 标注 + 区域裁剪** | `screenshot --annotated`、`screenshot-region`（按 ref/selector 裁剪） |
| 管理 | `BrowserPaneManager`（40 方法接口）+ `RemoteBrowserPaneManager` / `null` 实现；实例有 `ownerType: 'session' \| 'manual'`、`isVisible`、workspace 绑定、工具栏 |
| 手册 | `apps/electron/resources/docs/browser-tools.md` + `browser_tool --help` 自描述 |

**实测真实路径**（替换我之前写错的 `browser-pane-manager.ts`/`browser-cdp.ts`）：
`packages/server-core/src/sessions/RemoteBrowserPaneManager.ts`、`handlers/browser-pane-manager-interface.ts`、`packages/shared/src/agent/browser-tools.ts`、`apps/electron/src/renderer/atoms/browser-pane.ts`、`renderer/browser-toolbar.html`、`packages/ui/.../BrowserControls.tsx`。

**结论**：选元素 / 截图 / 区域裁剪 / (agent 用的)标注 —— **craft 工具层已有**。我们**不重造**，只加人类层。

## 2.1 · 浏览器自动化外部参考的取舍（2026-06-19）

用户提到的 CloakBrowser、browser-harness、OpenCL/OpenClaw 都和“让 agent 更好控制浏览器”有关，但不能一刀切当插件接进来。

| 项目 | 当前定位 | Fleet 处理 |
|---|---|---|
| browser-harness | 薄 CDP harness，让 LLM 直接连真实 Chrome，并能在执行时补 helper / 自修复 | **吸收优点，不替换主栈**：学习自修复 helper registry、低层 CDP fallback、失败诊断、任务 replay；第一版实现仍挂在 craft `browser_tool` / BrowserPane / timeline 上 |
| OpenClaw | managed browser profile、loopback gateway、profile routing、浏览器/画布/节点/自动化工作台 | **黑盒学习产品模型**：学习隔离 profile、local gateway、profile 路由和安全审计提示；不复制源码，不引入第二套 agent platform |
| CloakBrowser | stealth Chromium / anti-detect browser，强调 bot detection bypass、指纹伪装、automation framework drop-in | **高风险黑盒**：不能作为默认插件或依赖；不用于绕过 bot detection、验证码、登录限制、平台风控或配额。最多作为兼容性/测试参考，且必须用户显式授权、独立标注风险 |

因此浏览器自动化增强路线是：

1. **保留 craft browser core**：继续用 BrowserPane、Electron CDP、`browser_tool`、permission、session timeline。
2. **补可靠性而不是换壳**：加 challenge/popup/download/iframe/alert 的 failure classifier、recovery plan 和 replay evidence。
3. **补 agent 可编辑 helper**：允许在 Fleet 自有 sandbox 中生成一次性页面 helper，但 helper 必须进 session event、可审查、可回滚，不能像外部 harness 一样静默改文件。
4. **补 profile 管理**：按 OpenClaw 思路做 `manual` / `session` / `review` / `external-ai` profile routing，但仍用 Fleet 权限、登录态提示和本地数据边界。
5. **不做 stealth 产品化**：D4 已明确只做合法 profile 切换，不做规避检测；CloakBrowser 类能力不得成为默认路线。

## 3 · 为什么 craft 几乎不让人手动操作（你的点 4 的答案）

不是缺功能，是**有意设计**：craft 把浏览器做成 session 里的**工具**，每个动作都走 `browser_tool` → 进**权限 + 证据 + EventStream（可回放）**。如果让人在工具之外自由点浏览器，这些动作就**不在可审计时间线里**，破坏"一切动作可审批/可回放"（`AGENTS.md` 规则 16/22）。它的 `--help` + `resources/docs/*.md` 就是"agent 用功能时读手册"的机制——CLI 式自描述工具。

> **所以人类层要顺着这套做**：用户的点选/标注/开关，最终也变成走同一套 pane-manager + 权限 + 证据事件，而不是另开一条不进时间线的"人类暗管"。这样既给人控制权，又不破坏 craft 的审计模型。

再补一条更重要的方向：Fleet 不是传统“人类编辑器 + AI 聊天助手”。它继承 craft agent-native 原则，新增的人类操作面板必须同时是 AI 可调用的软件能力。后续浏览器选择、批量注释、Artifact Studio 编辑、资源库保存都应由统一的 `DesignAction -> DesignPatch -> SessionEvent` 驱动。

> **当前分支状态（2026-06-22）**：craft 原有 BrowserPane/CDP/annotation 可用，但 docked Stage、人类单选/框选/多选、批量注释和 Comment AI 尚未落入当前分支。旧工作树相关实现只能作为候选 diff，不能标为完成。

## 4 · 浏览器阶段真正要做的（人类层 + 设计工作流增量）

1. **停靠面板（最高优先级）**：把浏览器实例渲染在**聊天右侧面板**（而非新窗口）。产品形态应接近 Codex/Claude 桌面版的侧边浏览器：主聊天不离开当前 session，浏览器在右侧可展开/收起、可调整宽度、可与当前消息/证据联动。craft 已有 `browser-pane` atom + 工具栏 + `isVisible`/workspace 绑定，下一步不是再弹 BrowserWindow，而是把它**停靠**进主界面右侧。
2. **人工开/关**：UI 给人**主动 open/close/聚焦**按钮，写成 `ownerType:'manual'` 实例（craft 已支持 manual 所有权）。
3. **人点选元素**：注入 overlay 让**用户**鼠标点选 → **优先复用 craft `snapshot` 的 ref/可达性信息**，必要时补 selector/outerHTML。
4. **框选 + 多选**：用户拖出矩形框，系统收集框内元素并形成 `DesignSelection`；支持 Shift/Command 增删选中项。
5. **批量注释**：对 selection set 一次写批注，保存截图、boxes、可达性摘要、DOM 摘要和用户文字。
6. **Comment AI**：把选区证据带进下一条消息，让 Agent 只改这些区域或围绕这些区域解释问题。
7. **Artifact Studio 入口**：普通网页默认只注释；Fleet/Open Design artifact 支持手动微调，包括文本、链接、颜色、字体、间距、圆角、token、图片、视频、形状、蒙版、滤镜和层级。
8. **媒体插入与剪切蒙版**：图片/视频拖入 artifact 后可调位置、尺寸、旋转；可创建矩形/圆角/圆形/多边形/SVG path 蒙版，并在蒙版内部平移/缩放/旋转素材。
9. **字体/文字编辑**：连接本机字体、项目字体、合法网络字体；编辑文字、font family、weight、size、line-height、letter-spacing、variable axes 和 AI 文字特效。
10. **颜色/品牌编辑**：色板、渐变、吸管、截图/图片取色、品牌 token、语义色、对比度检查，网站编辑中可批量换色。
11. **动画生成和编辑**：对选区套 entrance/exit/loop/hover/scroll 动效，编辑 keyframe、duration、delay、easing、timeline，并保存到动画库；网页导出优先 CSS/WAAPI/SVG/Lottie。
12. **形状与 Draw-to-Implement**：用户可直接画矩形、圆形、线条、箭头、多边形；自由草图可保存为注释，让 AI 实现成 SVG/CSS/React。
13. **侧边库**：媒体库、字体库、色板库、动画库、UI 效果库、组件库、网页/APP/PPT 骨架模板可在侧边栏浏览、搜索、拖入当前 artifact。
14. **拖动/重排**：只对 artifact 的 editable region 开放；输出 reorder、grid span、alignment、gap、尺寸、旋转等语义 patch，不默认写自由 absolute positioning。
15. **人手标注**：截图上叠 canvas 供**用户**画框/批注（区别于 craft 的 `screenshot --annotated` 是 agent 给自己标 ref）。
16. **证据入 timeline**：人产生的 {元素 ref/outerHTML、截图、批注、selectionId} → `SessionEvent`，Agent 可引用。
17. **RPC**：新增标 `LOCAL_ONLY`；走 craft permission。

## 4.1 · 设计选择模式最小契约

| 能力 | 最小结果 | 失败/降级 |
|---|---|---|
| 单选 | 返回 1 个 ref/selector/box/name/role/text + region screenshot | 跨域 iframe 只能截图和坐标，不承诺 DOM |
| 框选 | 返回矩形内 N 个候选元素，按可见面积、层级、交互性过滤 | 元素过多时截断并提示用户缩小范围 |
| 多选 | selection set 可增删、清空、命名 | 页面刷新后 selection 失效，保留历史证据但不能继续编辑 |
| 批量注释 | 注释关联 selection set 和截图，进 session timeline | 无 session 时保存为本地草稿或提示绑定 session |
| 批量编辑 | 只对 artifact / editable region 开放；支持尺寸、圆角、颜色、阴影、滤镜、对齐、层级 | 普通网页显示“只能注释，不能直接编辑远程站点源码” |
| 媒体编辑 | 图片/视频插入、替换、裁切、蒙版、内部缩放/移动/旋转 | 原素材不破坏，保存 asset + transform 参数 |
| 字体/文字编辑 | 本机/项目/网络字体、字号、字重、行高、字距、变量字体轴、文字特效 | 字体授权不明时只可本机预览或私有引用，不打包公开模板 |
| 颜色编辑 | 色板、渐变、吸管、品牌 token、图片取色、对比度检查 | 优先写 token，不散落内联颜色 |
| 形状编辑 | 基础形状直接落 SVG/CSS，自由草图交给 AI 实现 | 复杂草图先作为 annotation，不假装已经可编辑源码 |
| 动画编辑 | 动画 preset、关键帧、timeline、easing、duration、hover/scroll/loop | 普通网页降级为注释；artifact 才写 motion patch |
| 拖动/重排 | 只生成语义布局 patch | 无 editable metadata 时降级为注释/Comment AI |
| 资源库 | 保存当前选区为组件/效果/模板，在侧边栏复用 | 未记录来源/许可证的外部素材不可自动公开分发 |
| Agent-native 编辑 | 人类 UI 与 AI 工具调用同一套 `DesignAction` | 禁止 UI-only state、临时 DOM mutation、不可回放私有画布状态 |

## 5 · 同步登录态（最佳方案）

- **默认**：App 内**持久 profile**（登录一次长期保留）。
- **可选**：**CDP 连你真实的 Chrome**，直接用已登录会话——什么都不复制。
- **不做**：抽取/解密浏览器 cookie（加密、易碎、安全雷）。
- 让 Agent 以你身份操作敏感站点 → 必须接权限 + 证据链。

## 8 · executor 必读：精确技术说明与坑

1. **先用 craft 已有的**：选元素优先用 `snapshot` 的可达性 ref（比自写 querySelector 稳）；截图/裁剪用 `screenshot-region`，**别另写一套 CDP 截图**。
2. **人点选 overlay 的坐标坑**：高亮/裁剪用 CDP box + `devicePixelRatio`，别用 DOM `getBoundingClientRect` 当截图像素；高 DPI / 缩放 / 滚动后会对不齐。
3. **iframe 跨域**：跨域 iframe 取不到 DOM → 只截图不取 DOM，别假装拿到。
4. **SPA 动态**：存"快照时刻"的 ref/outerHTML + 截图，别事后重查。
5. **不另起浏览器栈**：挂在 `BrowserPaneManager` 上；新增 RPC `LOCAL_ONLY`。
6. **DoD 加测**：人工 `open` 的 `manual` 实例与 agent 的 `session` 实例并存不串；高 DPI/缩放/滚动后标注对齐。
7. **多选/框选 DoD**：框选结果必须保存框选矩形、每个元素 box、页面 URL、viewport/dpr/scroll、截图和生成时间；页面刷新后不可继续编辑，只能作为历史证据引用。
8. **拖动/编辑 DoD**：只对带 editable metadata 的 artifact 开放；普通网页和跨域 iframe 不直接 patch。
9. **媒体/蒙版 DoD**：图片/视频编辑保存原素材 hash、MIME、尺寸、来源和非破坏性 `mask + mediaTransform + effects`；导出时再编译到 CSS/SVG/HTML。
10. **字体/颜色 DoD**：字体记录 family、format、source、license、是否可打包；本机字体默认只引用。颜色保存为 token/palette，并检查基础对比度。
11. **动画 DoD**：动画保存为 `AnimationTimeline`、`Keyframe`、`MotionPreset`，网页优先 CSS/WAAPI/SVG/Lottie，视频导出后续再编译；普通网页不直接 patch 动画。
12. **库 DoD**：自建库条目必须记录来源、版本、预览图、适用 surface（web/app/deck/product page）和是否可商业复用；未知许可证素材不得默认公开复用。

## 10 · 重启校准（2026-06-19）

浏览器与网页标注的第一落点必须是 **docked BrowserPane**：

- 浏览器停靠在主工作台 Stage 内，不新建独立页面/窗口。
- 浏览器 toolbar 直接显示「选择 / 框选 / 标注 / Comment AI / 保存证据」等入口。
- 普通网页只读：可以选择、注释、截图、整理证据、发给 Agent；不能直接改远程网页源。
- editable artifact / local preview 才进入 Artifact Studio，做图片、视频、形状、蒙版、裁切、参数、组件库和模板库编辑。
- 所有选择、标注、编辑必须进入同一套 `DesignAction -> DesignPatch -> SessionEvent`，带 actor、权限、证据和回滚点。

# 源码参考使用规则与索引

> 当前原则：Fleet 直接基于 craft-agents-oss 二次开发。源码复用必须先过许可证和产品主线两道关。

## 1 · 许可证红绿灯

| 区域 | 项目 | 规则 |
|---|---|---|
| 绿灯 | `源码参考/craft-agents-oss` | Apache-2.0，已经作为 `app/` 主基座，可直接改 |
| 绿灯 | `源码参考/AionUi` | Apache-2.0，可直接迁移 CLI Runtime/custom agent/ACP/进程生命周期/Agent/群聊/Skill 运行相关源码或模式 |
| 红灯/黄灯/未核准 | Kun、Cherry Studio、Zed、LobeHub、Warp、OpenCode、cmux、golutra、multica、hermes-agent、cc-switch 等 | 未单独核准并写入绿灯表前只能黑盒参考，不能复制源码进 `app/` |

硬规则：

- MIT/Apache-2.0 只是进入候选池，不自动等于绿灯。
- 只有被加入上方绿灯表，且标明核准版本/commit、允许复制范围、归因方式后，才允许复制源码。
- 未核准前，即使 LICENSE 看起来宽松，也只能参考产品行为、公开文档、交互目标和能力清单。
- 黑盒参考项目禁止复制源码、测试、配置、类型定义、样式、资源文件、文案和结构性实现。
- `golutra` 本地许可证为 BSL 1.1，按高风险黑盒处理。

## 3 · 复用要求

每个功能模块动工前必须写清：

1. craft 中已有的路径和能力。
2. AionUi 是否有可直接迁移的绿灯实现。
3. 是否需要黑盒参考其它项目，只能写“参考点”，不能复制代码。
4. 需要保留的 Apache-2.0 版权/NOTICE。
5. 验收命令和用户可见路径。

每次从 craft/AionUi 迁移源码，还必须更新来源清单：

| 字段 | 要求 |
|---|---|
| Fleet 模块 | 新代码服务哪个 Fleet 功能 |
| 来源项目 | `craft-agents-oss` 或 `AionUi` |
| 来源路径 | 原始文件/目录路径 |
| 来源版本 | commit/tag/date |
| 迁移方式 | 原样复制、局部复制、改写、模式迁移 |
| 许可证处理 | 是否保留文件头、SPDX、NOTICE/归因 |
| 修改说明 | Fleet 做了哪些改动 |

建议记录到 `docs/源码迁移清单.md`。

## 4 · AionUi 迁移归因规则

- 复制整文件时保留原文件头、版权声明和 SPDX。
- 改写或拆分 AionUi 文件时，在新文件头或邻近注释标明 `Portions derived from AionUi`，并附原路径、Apache-2.0、迁移日期。
- 在产品第三方声明或 NOTICE addendum 中加入 AionUi 归因；若未来 AionUi 出现 NOTICE 文件，必须合并保留。
- 不默认复制 AionUi logo、品牌名、截图、gif、图标等商标/品牌资产，除非用户单独确认。
- 迁移任务说明中必须列明来源项目、文件路径、迁移方式和验证命令。

## 5 · 禁止事项

- 禁止把旧自研 `app/src` 架构补回来。
- 禁止从 Kun、Cherry、Zed、LobeHub、Warp、OpenCode、cmux、golutra、multica、hermes-agent、cc-switch 等红灯/黄灯/未核准项目复制源码。
- 可以基于产品需求自研 UI，但不得复制未核准项目的源码、结构性实现、品牌资产、截图切图或高度近似布局。
- 禁止把 Git、浏览器、Skill、MCP 都塞进设置页；这些必须成为工作台能力。

# 14 · 源码参考目录专项审计

> 状态日期：2026-06-22
> 范围：`源码参考/software/` 与 `源码参考/plugins/` 下当前本机实际存在的参考项目。
> 目的：把每个参考项目的许可证、当前本地 commit、官方 GitHub 状态和 Fleet 可用边界列清楚，避免后续智能体凭文件夹名误判能复制源码。
> 产品取舍：每个项目具体“只学哪一招、不要学什么、落到 Fleet 哪里”，见 `docs/29-开源项目参考取舍清单.md`。

## 1 · 总规则

- **能直接复制源码的绿灯项目只有当前绿灯表里的项目**：`craft-agents-oss`、`AionUi`、`open-design`、`rtk`、`codegraph`、`DeepSeek-Reasonix`、`deepcode-cli`。
- **目录分类只表示参考方式，不表示许可证许可**：`software/` 放完整软件/客户端/平台，`plugins/` 放可作为能力模块、sidecar、CLI、库或引擎参考的项目；红绿灯仍以本文和 `docs/26` 为准。
- **MIT / Apache 不自动等于绿灯**。CowAgent、cc-switch、headroom、repomix、markitdown、OpenHands、hermes-agent、letta-code、mem0、mempalace、opencode、supermemory 等虽然显示宽松许可证或局部宽松许可证，但未获用户明确核准并写入绿灯表前，只能黑盒参考或 optional sidecar。
- **红灯/高风险项目不能复制源码、测试、类型、配置、样式、资源或结构性实现**。可以学习产品边界、交互目标和错误处理，但实现必须自研或来自绿灯项目。
- **不得把文件夹存在等同于完整克隆**。必须检查该目录自己的 `.git`、remote、HEAD、许可证和关键源码；从父仓库继承到的 `git rev-parse` 结果无效。
- 2026-06-22 新增的设计/视频候选已记录在表中；它们仍是候选/黑盒，不因 MIT/MPL 自动升为绿灯。

- SVGator animation templates：外部模板/产品形态参考，学习动画模板库、SVG/Lottie/GIF/video 多格式导出和可编辑 starter project；不抓取私有项目，导入模板必须看授权。
- KDE Kdenlive：GPL-3.0，当前只能黑盒学习时间线、轨道、剪辑、转场、音视频效果概念；不能复制源码进 Fleet。
- Remotion：React 程序化视频参考；官方提示特殊许可证和 company license 场景，不能默认复制源码或作为内置依赖。
- HyperFrames：Apache-2.0、HTML-native、agent-friendly、deterministic video/render 强候选；未获用户明确写入绿灯表前仍只黑盒参考，不复制源码。
- OpenUI：MIT、完整参考库位于 `源码参考/plugins/openui`；它适合研究“让模型只能生成已注册组件”的组件白名单、由组件库生成 prompt、增量解析与流式渲染。Fleet 后续可把这种模式用于 Artifact / 报告 / 表单等受限生成界面，但不能替代现有 WorkbenchShell、SessionManager、permission、timeline 或 `DesignAction -> DesignPatch -> SessionEvent` 主链。

执行顺序：先在原浏览器标注页做设计选择、框选、多选、批量注释和 Comment AI；再补 `DesignAction` 共用动作契约；随后做 Typography/Color v1、Open Design artifact 受控编辑、Motion/Animation v1；最后接 Figma/Stitch bridge 和视频导出。

上下文效率执行顺序：先做 Usage Report，再做 ProjectPack/MarkItDown sidecar，再做 External Review v1，最后接 rtk/codegraph/Reasonix/Headroom 组合优化。所有外部网站审查必须先过用户确认、secret scan 和数据外发记录。

## 3.4 · LobeHub 黑盒参考补充

2026-06-20 本地复查 `源码参考/software/lobehub` 后确认：根许可证为 **LobeHub Community License**，基于 Apache-2.0 但对 derivative work distribution 要求商业授权；因此 Fleet 当前不能复制它的源码、类型、测试、配置、样式、UI 结构、文案或资源。它的价值是产品形态和模块边界。

可学习的产品能力：

- **Chief Agent Operator**：把 Agent 作为工作单元，由一个软件级管理者负责招募、调度、总结和交付，而不是只堆多个聊天窗口。
- **Agent Builder / Agent Groups**：用自然语言创建 Agent、把多个 Agent 组成任务组、按任务分配角色；Fleet 落到 `docs/17-Agent协作与管理Agent模型.md` 的管理 Agent / 项目 Agent 两层结构。
- **Project / Workspace / Schedule / Pages**：把任务组织成项目、工作区、定时运行和共享页面；Fleet 落到 craft session、workspace、timeline，不新建第二套 store。
- **Personal Memory / 白盒记忆**：记忆要结构化、可见、可编辑、可删除；Fleet 落到 `docs/05-记忆系统方案.md` 的本地分级记忆。
- **Skill / MCP / 插件市场**：把工具能力作为可发现、可启用、可维护的能力目录；Fleet 仍以 craft Skill/MCP + AionUi Skill 注入为实现来源。
- **Context Pipeline / file-loaders / web-crawler**：文件、网页、知识库先转成标准文档，再进入上下文管线；Fleet 落到 `docs/16-上下文效率与外部AI审查方案.md`，和 Repomix / MarkItDown / codegraph / rtk / Headroom 组合。
- **服务模型 / 内部任务模型路由**：LobeHub 把"新建助理、话题自动命名、AI 图片话题命名、消息翻译、会话历史压缩、档案信息生成、记忆分析、记忆图像写入"拆成可配置的服务模型。Fleet 应学习这个产品边界：主聊天模型、管理 Agent 模型、记忆模型、压缩模型、命名/翻译/总结等后台小模型必须可分开配置和观测，而不是只有一个全局模型下拉框。
- **系统工具 / 运行环境健康面板**：LobeHub 对 `lobehub` CLI、node、python、npm、bun、bunx、pnpm、uv 等运行时做版本、路径、可用性展示。Fleet 应把 CLI Runtime、ProjectPack、MarkItDown sidecar、代码图谱、浏览器自动化、设计/视频导出依赖都纳入同类"系统工具"面板，显示可用/不可用、版本、路径、复制路径和修复建议。
- **Model bank / tool runtime / reports**：多 provider、多 tool runtime、工作报告与交付检查对 Fleet 有产品参考价值，但实现必须自研或来自绿灯项目。

执行边界：LobeHub 不能升为默认实现来源。后续任何 agent 若声称“按 LobeHub 做”，必须写清楚是**行为参考**，不能复制文件、目录结构、组件、prompt、schema 或 UI。

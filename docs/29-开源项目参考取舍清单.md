# 29 · 开源项目参考取舍清单

> 状态日期：2026-06-22
> 目的：把 `源码参考/software/` 和 `源码参考/plugins/` 逐项看完后，提炼每个项目对 Fleet 真正有用的一招，并明确不要学什么。这个文件解决“参考什么”，不改变 `docs/26` 的许可证红绿灯。

## 0 · 总原则：只取一招，不换路线

不要邯郸学步。Fleet 的主线已经定了：**craft 基座 + 一条 session/timeline/permission 主干 + 统一工作台 + 管理 Agent / 项目 Agent + 上下文效率中心 + 设计工作流**。

看开源项目时只问三件事：

1. 它有没有一个 Fleet 现在缺的**单点能力**。
2. 这个能力能不能接进 craft 现有 `SessionManager`、tool、permission、timeline、settings。
3. 接进去后会不会形成第二套 UI、第二套 session、第二套权限或第二套记忆。

答不上来就只放货架，不进近期路线。

## 4 · 反面纪律

以下做法一律不采纳：

- 看到一个项目有完整平台，就把 Fleet 也改成完整平台。
- 因为某项目 UI 好看，就复制它的布局、组件、文案或信息架构。
- 因为某项目支持很多 provider/agent，就在 Fleet 里堆一排未接线按钮。
- 因为某项目能 hook/代理/切换 CLI，就绕过 craft permission 和 timeline。
- 因为某项目宣称省 token，就把估算值写成真实省钱。
- 因为某项目有 memory，就默认上传用户数据或建立不可删除画像。
- 因为某项目有浏览器自动化，就替换 craft BrowserPane 主栈。

Fleet 的判断标准只有一个：**这项参考能不能让当前主干更完整、更稳定、更可审计**。不能，就暂时不做。

## 5 · 下一步落地顺序

1. **先做团队编排脊柱**：craft session + AionUi Team/ACP/Skill，Warp 只学运行态。
2. **再做全部文件 / Library 契约**：所有创作面共享本地资产来源。
3. **再做无限画布与 AIGC 最小闭环**：先核 openpencil 绿灯范围；生成统一走 External Job。
4. **再做网页/文档与视频剪辑**：BrowserPane/文档模型走 craft；视频候选优先核 opencut-classic。
5. **治理簇只收口**：Context、External Review、Memory、Decision 不再扩独立面板。

这份清单后续新增项目时继续维护：先归入 `software/` 或 `plugins/`，再补一行“可参考的一招 / 不要学什么 / Fleet 落点”。

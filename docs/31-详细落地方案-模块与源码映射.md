## 1 · 统一契约：脊柱共用，编辑分面（design.ts §1 锚点）

这是整个项目的承重墙，已落在 `app/packages/shared/src/protocol/design.ts`。本文补全它的“为什么这样切”和“各字段如何落到各面”。

### 1.1 · 一句话契约

**统一在“谁做了什么·准不准·可不可回放”，分开“用哪种 op 改内容”。**

- 共用（全局唯一，脊柱）：`session` / `SessionEvent`（一条 timeline）/ `permission` 门 / `actor` 身份（`agentId·role·runtime`）/ runtime 接入（ACP·CLI·API）/ Action Ticker / 跨面轻量 `DesignSelection` 描述符 / 动作信封 `DesignAction` / 资产 Library / 外发 Job。
- 分开（按面原生引擎）：设计=openpencil 文档树、代码=file diff、文档=craft 文档模型、浏览器=BrowserPane/CDP、视频=opencut-classic 时间线、活网页=见 §4.2 裁决。

### 1.2 · 已落地的契约对象（design.ts 现状，保留）

| 契约 | 角色 | 现状 |
|---|---|---|
| `ActorRef`（user/agent + agentId/runtime/role/displayName） | 谁做的 | ✅ 已定义 |
| `WorkbenchObjectType`（code_symbol/design_node/doc_block/media_asset/clip/track/keyframe/board_cell/shot/caption/audio_track/knowledge_card/library_item + `(string&{})` 扩展位） | 选区指向的对象类型并集 | ✅ 已定义 |
| `WorkbenchSurface`（browser/artifact/code/document/timeline/board + 扩展位） | 对象所在面 | ✅ 已定义 |
| `WorkbenchObjectRef`（type+surface+**不透明 locator**+预览） | 单个对象引用；spine 不解释 locator | ✅ 已定义 |
| `DesignSelection`（objects[] + createdBy + label） | **一套**选区，多选/框选/跨面进同一集合 | ✅ 已定义 |
| `DesignAction`（selectionId + actor + op + origin） | **一套**动作信封 | ✅ 已定义 |
| `DesignActionOp`（set_style/set_layout/set_transform/insert_asset/set_mask/timeline_op/board_op/doc_edit/code_patch/annotate + `kind:string` 扩展位） | op 联合，可注册扩展 | ✅ 已定义 |
| `DesignPatch`（forward + **必有 inverse** + status preview/pending/committed/rolled_back） | 可回滚结果 | ✅ 已定义 |

### 1.3 · 对 design.ts 的唯一修正（docs/30 已裁决）

`DesignActionOp` 里那些带 `payload: unknown` 的 op（`timeline_op` / `board_op` / `doc_edit` / `code_patch` / `set_mask`）**不要再试图在 spine 侧穷举/解释其内容**。它们就是“动作信封 + 指向某个面原生 patch 的句柄”：

- `forward`/`inverse` 对 spine **不透明**：spine 只负责登记、过 permission、emit、记账、回放索引。
- 真正算 forward/inverse + 应用 + 回滚，是该面**原生引擎适配器**（`DesignPatchApplier`，已在 `design-engine.ts` 留好接口）的事。
- `set_style`/`set_transform`/`set_layout`/`annotate` 这种**跨面通用的轻动作**可以保留 spine 可读结构（用于 Inspector 直接编辑窄屏简单属性），但它们的应用仍由对应面 applier 落地。

**这就是“over-unify 修正”的代码级表达**：`DesignEngine` = 瘦桥（事务/账本/状态机/事件/权限/回放），各面 applier = 原生引擎适配器。`design-engine.ts` 当前实现已经是这个形态（见其文件头注释），**方向正确，只需删掉 iframe applier、换 openpencil applier**（见 §10 S1）。

## 3 · 六动词跨面 Agent 工具契约（推广 pen-mcp）

`docs/30` §4 定了方向：每个面给 agent **同一组结构化动词**，不让 agent 推 DOM selector、不让它截图找按钮。openpencil 的 `pen-mcp` 已经是这个范式的现成实现，**把它的形状固化为所有面的契约**：

| 动词 | 语义 | 设计面（openpencil 现成） | 代码面 | 文档面 | 视频面（opencut-classic 抽） | 浏览器面 |
|---|---|---|---|---|---|---|
| **read** | 读结构成 JSON | `read_nodes`/`batch_get`/`snapshot_layout`/`find_empty_space` | 符号/文件树（codegraph） | 块树 | 轨道/片段表 | DOM 选区证据 |
| **select** | 取/设选区 | `get_selection` | 符号范围 | 块范围 | clip+时间区间 | 元素/框选 |
| **mutate** | 结构化改 | `insert_node`/`update_node`/`move_node`/`delete_node`/`replace_node`/`import_svg` | file diff | 块 replace/insert | trim/split/speed/reorder/caption | （远程只读：不可改源站） |
| **intent** | 高层意图 | `design_skeleton`/`design_content`/`design_refine` | “重构此函数” | “重写这段” | “把这段配音对齐” | “框这三块卡片给我做参考” |
| **undo** | 撤销 | `HistoryManager`（Ctrl+Z 级） | git/diff 级 | 块 history | 时间线 history | n/a |
| **explain/handoff** | 导出/解释 | `get_design_md`/`export_design_md`/DESIGN.md | diff 摘要 | 导出 md | 导出 EDL/渲染 | 证据包 |

落地约束：
- 每个面的工具集都注册成 craft 的 **session tool / MCP server**，调用必走 `DesignEngine.proposeAction`（信封）→ permission → 面 applier → `SessionEvent`。**agent 不得绕过信封直接改内容。**
- 工具调用事件带 `agentId/runtime/role`（AGENTS 规则 15），进 Action Ticker 分流。
- 人类 UI 控件与 agent 工具**一一对应**：design-canvas 上拖一个节点 = `move_node`，agent 调 `move_node` = 同一条 patch 通道（D7/规则 19）。

openui 降级为生成工具（§2），所以“活网页可编辑面”的裁决：

## 5 · External Execution Bridge（外发统一成一个 Job 模型）

`docs/30` §6 已裁决：代码审查/生图/图转 3D/生视频/剪辑渲染/发布/外部 AI 审查**本质同一件事**——派给外部 runtime/服务/站点，过 permission，跟踪状态，结果回 timeline+Library。统一成一个 Job 模型，External Review **降为其一个 type**。

```
Job { id, type, 输入引用(选区/文件/artifact/bundle), 目标(provider/runtime/site),
      permission(按敏感度 L0-L3), status, 结果(→Library/surface), 成本(真实/估算/未知), provenance, 回放点 }
  └─ emit SessionEvent(带 actor) → 一条 timeline · Action Ticker · 可授权可回放
```

## 13 · 本轮优化评审：每个模块是否最优 + 增 / 减 / 换（2026-06-22 第二轮）

> 触发：用户质疑“整套方案是不是最优、每个模块有没有更好选择、有没有要增减的功能”。本节是把剩余模块文档（`docs/05/16/20/29` 等）和**未深读的克隆源码**逐项核完后的结论。判断标准只有一条：**让“人机共编一条时间线”这个命题更完整、更稳、更可审计**（`docs/29` §0），不是堆功能。

### 13.1 · 模块最优性逐项裁决

| 模块 | 当前选择 | 是否最优 | 裁决 |
|---|---|---|---|
| 设计画布 | openpencil | ✅ 最优 | 同栈、MIT、文档模型+引擎+24 MCP 工具+history 全现成，无更优替代（penpot 异栈、open-pencil Vue）。**保留** |
| 活网页 artifact | openpencil codegen（openui 降级） | ✅ 修正后最优 | openui 本地无引擎源码、本质生成工具→降生成 Job 参考。活网页可编辑面 = openpencil 文档 + `pen-mcp/codegen-*`。**确认降级** |
| 浏览器/网页标注 | craft BrowserPane/CDP | ✅ 最优 | 是脊柱本身，换栈违反铁律 22。**保留** |
| 代码面 | craft file diff + codegraph(绿灯) | ✅ 最优 | **保留** |
| 文档面 | craft 文档模型 | ✅ 最优 | craft 本就是 doc agent。**保留** |
| 视频编辑器 | ~~opencut(rewrite 空壳)~~ → **opencut-classic** | ✅ 换源后最优 | opencut-classic 690 文件含 timeline+**GPU 渲染+scene-exporter+export**，是完整剪辑闭环。**换源（已记 §2）** |
| 网页动画→视频渲染 | 模糊“Chromium/HyperFrames 类” → **hyperframes** | ⚠️ 应明确 | **hyperframes(1273 文件, Apache-2.0, HTML-native deterministic render)** 是 `video_render` 的明确强候选，写入绿灯候选名单（许可证用户拍）。比裸 Chromium 截帧稳 |
| Figma 互通 | 独立 M3 bridge | ⚠️ 可大幅简化 | openpencil **`pen-figma`(24 文件)** 已含 fig-parser+全套转换器+剪贴板。**取消“独立 Figma bridge 工程”**，直接吸收 pen-figma，Figma 导入/粘贴随设计面一起来（M3→可提前） |
| 多 Agent/团队 | AionUi(绿灯) | ✅ 最优 | **保留** |
| 分层记忆 | craft 七分区 + mem0/CowAgent 算法黑盒 | ✅ 最优 | 不 fork Python 引擎；UX 抄 letta 记忆查看器。**保留（冻结扩张）** |
| 上下文/审查 | repomix/markitdown/codegraph/rtk(部分绿灯) | ✅ 够用甚至超前 | **保留并封顶只收口** |

**结论**：架构层（脊柱+各面原生引擎+Job 桥）无更优解，已是最优。模块层只有两处实质变动——**视频换 opencut-classic（已改）、网页动画渲染锁定 hyperframes**；一处简化——**Figma 吸收 pen-figma、砍掉独立 bridge**。

### 13.2 · 建议“增”的功能（让创作台真能交付高质量）

| **设计品味/设计技能层** | 否则 AI 出的 UI 是“通用 slop”。这是创作台质量的命门 | **open-design(绿灯)** 的 `craft/`(anti-ai-slop/laws-of-ux/accessibility/animation-discipline/color/state-coverage) + `contracts/critique` + `pen-ai-skills/style-guide` → 作为设计 Agent 的 Skill/校验层，进 permission/timeline | S2 后期接，**高** |

### 13.4 · 一条要警惕的“伪模块”重复

“无限画布”与“Artifact Studio”**不是两个引擎**，是**同一个 openpencil 文档模型的两种入口取景**（画布=从空白/素材编排进入，artifact=从 AI 生成结果进入深编辑）。实现时只建一套 openpencil 设计面 + 两个进入路径，**不要做成两套引擎/两套选区/两套 history**（否则违反 `docs/01` §3 五个唯一）。
